# 模块 07（stage2）练习：递归回溯

> 分层：A 概念 / B 动手 / C 挑战。🕷 = 高频易错。

## A 概念题

**A1** 写出回溯的三大步（中英文）。Unchoose 在什么前提下可以省略？
*考察点：Choose/Explore/Unchoose；传值时副本自动恢复。*

**A2** 🕷 a) 背包问题两种贪心策略分别怎么翻车的（官方两次结果）？b) 贪心失败的根本原因？
*考察点：16 vs 19、162 vs 176；物品价值依赖剩余容量=耦合决策。*

**A3** 什么是"arm's-length recursion"？官方为什么反对它？解法三的替代方案靠什么兜底、付出了什么代价？
*考察点：调用点躲避 vs 基例兜底；代价=valueSoFar 第三参数。*

**A4** `return fA() || fB()` 为什么可能比"先算两个再 or"快得多？这个惯用法在回溯里的语义叫什么？
*考察点：短路求值；找到即返回的剪枝。*

**A5** 为什么缓存背包结果不能用 `Map<重量, 价值>`？官方给出的反例机制是什么？
*考察点：同重不同值撞键。*

**A6** 背包最坏/最好复杂度各是多少？分别对应什么输入形态？
*考察点：O(2ⁿ) 全装得下 / O(n) 全太重。*

## B 动手题

**B1（幂集生成与计数）**：
1. 实现 `printSubsets(soFar, rest)`，对 `{a,b,c}` 输出全部 8 个子集
2. 改造成 `countSubsets` 返回数量，验证 2ⁿ
3. 🕷 思考+验证：输出里有 `{b,a}` 吗？为什么不可能有？
*考察点：二元决策树；计数版只改基例与 return；集合序的天然去重。*

**B2（🕷 等和分区 + 撤销实验）**：
1. 实现和追踪版 `isPartitionable`（注意尾部删除 + 放回）
2. 测 `{1,1,2,3,5}`（true）、`{1,4,5,6}`（false）、空集（true：0=0）
3. **注释掉 `v.push_back(x)` 那行**重测 `{1,4,5,6}`——还正确吗？解释污染如何导致错误
4. 思考：为什么官方强调从**尾部**删除而不是 `erase(begin())`？
*考察点：Unchoose 的存在性证明（删掉就坏）；O(1) vs O(n) 删除。*

**B3（背包三连——官方数据实测）** 定义 `struct Item {int w, v;};`：
```cpp
// 测例一（最优 19）：官方课堂用例
std::vector<Item> a = {{6,30},{3,14},{4,16},{2,9}};   int capA = 10;
// 测例二（最优 176）
std::vector<Item> b = {{4,40},{4,40},{6,47},{6,47},{7,58},{7,58},{5,33},{5,33}}; int capB = 15;
```
1. 实现两种贪心（按价值降序 / 按 v/w 降序），在两测例上复现官方翻车（16、162）
2. 实现下标 k 版正确解法，验证 19 与 176
3. 打印出最优解**选了哪些物品**（提示：加一个 chosen vector，choose 时压入、unchoose 时弹出）
*考察点：贪心反例复现；回溯保最优；解的回溯重建。*

## C 挑战题

**C1（N 皇后——本仓库延伸经典）** n×n 棋盘放 n 个皇后互不攻击（同行/列/对角线）。这是回溯的传世名题（官方讲义未含，作为配套经典）：
1. 逐行放置：每行试 0..n-1 列，检查与已放皇后的列/对角线冲突
2. n=4 输出所有解（2 个）；n=8 统计解数（**92**）
3. 复杂度上界是多少？剪枝（冲突检查）砍掉了多少无效分支？
*考察点：Choose(放)/Explore(下一行)/Unchoose(移除) 完整版；约束剪枝的威力。*

**C2（记忆化初试——官方预告的 DP 方向）** 下标版背包在外层加一个 `map<状态, int>` 缓存（状态=(k, capacity)）：对比 30 件随机物品下有无缓存的递归调用次数（加计数器）。调用次数降了多少？
*考察点：重复子问题可视化——为什么 DP 能把 2ⁿ 砍成 n·c。*

**C3（子集和判定）** 给定正整数集和目标 t，判定是否存在子集和恰为 t（如 {3,34,4,12,5,2}, t=9 → true，3+4+2）。用回溯实现并加**剩余和剪枝**：若当前和已超 t 整支剪掉。测试无解用例（t=1000）在有/无剪枝下的递归次数差异。
*考察点：显式剪枝（bound check）——官方 L11 提到但未展开的"好剪枝"在这里亲手补全。*
