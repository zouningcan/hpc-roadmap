# 模块 02（stage2）参考答案

## A1

有序（保持插入顺序）、下标 0..n-1 访问、同构（所有元素同类型）、底层连续数组、自动增长扩容。连续内存的两好处：**O(1) 下标随机访问**（一步算出地址）+ **缓存友好**（读一个元素顺带把整块搬进缓存，后续命中）——后者是 HPC 侧最重要却最隐形的一条。

## A2

`insert(0, x)` 要把现有 n 个元素**全部右移一格**给新元素腾位——每次 O(n)。官方实测：50 万元素时尾部 add 0.029s vs 头部 insert 9.794s ≈ **338×**。差距随规模拉大的原因：append 摊还 O(1)（偶尔扩容），head insert O(n)——n 翻倍，前者时间几乎不变，后者翻倍，比值指数式扩大。

## A3

a) r=行，c=列，永远行在前。b) row-major：同一行的元素在内存中连续相邻。c) 外层遍历列 = 每次内层步进都跳到下一行的同列位置——内存上大跨度跳跃，每次访问都可能缓存未命中（cache miss），而缓存命中/未命中差一个数量级以上。

## A4

不变——range-for 的 `int x` 是**每个元素的副本**，改副本无效。改成 `for (int& x : v)`（引用）才落在原容器上；只读遍历建议 `const int& x`。

## A5

`const vector<int>& v`：**引用（&）** 免整份拷贝（vector 可能几十 MB）；**const** 向编译器和读者承诺只读（误改编译期拦截）。修改型参数才去掉 const。

## A6

官方清单类别：全字母、非法字符在头/中/尾、交替出现、全非法字符、纯空白、空串、极短（1–3 字符）、超长、奇偶长度。方法论：**按"形态类别"系统性穷举**，不是随机凑数。

## B1

逐步：{15,20,18} → push_back → {15,20,18,33} → insert(位置2) → {15,20,**90**,18,33} → erase 首位 → {20,90,18,33} → push_back(v[0]+v[1]=110) → **{20,90,18,33,110}**。

## B2

预期形态：append 时间随 n **线性缓增**（甚至近乎平——摊还 O(1) 总量 O(n)）；head insert 随 n **平方级暴涨**（每次插入搬全部元素，总量 O(n²)）；n 每翻倍，比值大约再翻倍。你的具体数字与机器有关，看**趋势与比值**。

## B3 参考

```cpp
#include <vector>
vector<vector<int>> g(3, vector<int>(4, 0));
g[2][3] = 18;
for (int r = 0; r < (int)g.size(); r++)
    for (int c = 0; c < (int)g[0].size(); c++)
        if (!(r == 2 && c == 3)) g[r][c] = r + c;

bool inBounds(const vector<vector<int>>& g, int r, int c) {
    return r >= 0 && c >= 0 && r < (int)g.size() && c < (int)g[0].size();
}
```
和 = Σ(r+c)（r=0..2,c=0..3）+ 18-5（把 (2,3) 的 18 替换掉了原本的 5）= 36 + 13 = 49。去掉检查后 `g[5][5]`：外层越界读野指针——典型结果是**段错误（segfault）**，或毫无征兆的垃圾值（未定义行为）。

## B4

示例组：`""`→0、`"$*"`→0、`"abc"`→3、`"a1b2c3"`→3、`"1ab"`→2（尾部）、`"!!x"`→1（中部）、`"a b"`→2（含空白）、超长串→人工算一个。埋错验证：把 `isalpha` 误写成 `isdigit` 或漏掉某分支，assert 立刻炸——**测试的价值 = 它抓得住错**。

## C1

`__FILE__`/`__LINE__` 是**预定义宏**，编译时展开为当前文件名/行号——让失败报告自动定位。参数加括号是因为宏是**纯文本替换**：`EXPECT_EQUAL(x+1, 2)` 若宏内写 `a == b` 会展开成 `x+1 == 2`（恰好对），但 `a*2` 场景 `x+1*2` 就错了——加 `(a)`/`(b)` 保证任何实参组合都不变形。`do{...}while(0)` 让宏在 if/else 里当"一条语句"用。

## C2

版本 A（行优先）显著快于版本 B（列优先），常见差距 2–10×（视机器缓存）。加法次数完全相同 → 差距全部来自**内存访问模式**：A 顺着内存线性扫（预取器友好、缓存行全命中）；B 每步跳 16000 字节（4000×4B），几乎每次访问都 miss。这就是"**算法相同、访存不同、性能天差地别**"——HPC 优化的第一条物理定律。

## C3 参考

```cpp
void transpose(const vector<vector<int>>& src, vector<vector<int>>& dst) {
    int r = src.size(), c = src[0].size();
    dst.assign(c, vector<int>(r));
    for (int i = 0; i < r; i++)
        for (int j = 0; j < c; j++)
            dst[j][i] = src[i][j];
}
```
src 只读 → `const&`（免拷贝+防误改）；dst 是输出 → 普通引用（要写进去）。是的——**修饰词即合同**：调用者不看函数体就知道"我不会动你的 src，结果会写进 dst"。
