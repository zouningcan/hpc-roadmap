# 模块 03（stage2）：栈与队列

> **来源**：Stanford CS106B 2026 夏 L5《Stacks and Queues》
> https://web.stanford.edu/class/archive/cs/cs106b/cs106b.1268/lectures/05-stack-queue/
> **官方库 → 标准库映射**：`Stack<T>`→`std::stack<T>`、`Queue<T>`→`std::queue<T>`（差异见第 4 节，有个必踩的坑）。

## 0. 一句话定位

两个**限制操作集**的容器：栈（LIFO，后进先出）和队列（FIFO，先进先出）。限制操作不是缺陷而是设计——**更少的动作 = 更少的错法 + 更强的语义表达**（官方称之为"抽象的力量"）。

## 1. 栈（stack）：LIFO

只有五个动作：`push`（压入）、`pop`（弹出并返回栈顶）、`peek`（看但不拿）、`isEmpty`、`size`。**没有按值查找、没有随机访问**——你只能从顶上操作。

```cpp
std::stack<int> s;
s.push(10); s.push(20); s.push(15); s.push(12);
// 弹空输出：12 15 20 10（后进先出，逆序）
```

**现实模型与应用**：

| 类比 | 应用 |
|------|------|
| 一摞盘子（只能拿最上面的） | **函数调用栈**（函数一层层调用、一层层返回——第 6 模块递归的物理底座） |
| 浏览器"后退"按钮 | 撤销历史（undo 栈） |
| 反转任何序列 | 把 "muffins" 逐字符压栈再弹光 = "sniffum" |
| 计算器的心脏 | **后缀表达式求值**（本讲大案例，见第 5 节） |

## 2. 队列（queue）：FIFO

`enqueue`（队尾进）、`dequeue`（队首出）、`peek`（看队首）。排队买票：先来的先服务。

**应用**：抢购排队、打印机任务队列、游戏登录队列、——最重要的伏笔——**广度优先搜索（BFS）用队列，深度优先（DFS）可以用栈**（第 14 模块图算法的前置知识）。

## 3. 为什么要"阉割版"容器——抽象的力量

栈完全可以用裸 vector 模拟（`v.push_back` / `v.erase(v.end()-1)`）。官方观点：**能用 ≠ 应该**。用 `stack` 的三重收益：

1. **可读性即文档**：代码里出现 `stack`，读者立刻知道"这题的语义是 LIFO"
2. **杜绝错误姿势**：没有 find、没有中间插入——想犯错都没门
3. **改实现不改接口**：今天底层是 vector，明天换成链表（模块 11），调用方一行不改

## 4. 标准库的差异（🕷 必踩坑）

| 官方 Stanford 库 | `std::stack<T>`（我们用的） | 备注 |
|---|---|---|
| `s.push(x)` | `s.push(x)` | 相同 |
| `s.pop()` **返回**栈顶 | `s.pop()` **只是删除，不返回！** | 🕷 取值要用 `s.top()` |
| `s.peek()` | `s.top()` | |
| `cout << s` 直接打印 | ❌ 不支持 | 调试时自己循环导出 |

`std::queue<T>`：入队 `push`、出队 `pop`（同样**不返回值**）、看队首 `front()`、看队尾 `back()`。**取值+弹出的标准二连**：

```cpp
int x = s.top();   // 先取值
s.pop();           // 再弹出
```

🕷 另一个坑：**range-for 不能遍历 stack/queue**（它们不提供迭代器——"限制操作集"的贯彻）。要遍历就得弹光（破坏性）或用别的容器。

## 5. 本讲大案例：后缀表达式（postfix）求值

中缀 `3 + 5 * 2` 人看着舒服，但**括号和优先级对机器是灾难**。后缀（RPN，逆波兰式）把运算符放后面：`3 5 2 * +`。求值算法是栈的教科书应用：

> 从左到右扫描：**数字压栈；遇到运算符就弹出两个数、算完把结果压回**。扫描结束时栈里剩的一个数就是答案。

官方例：`3 5 2 * + 12 2 3 * / -` = ?

```
3 → [3]                    5 → [3,5]                2 → [3,5,2]
* → 弹 5,2 算 10 → [3,10]  + → 弹 3,10 算 13 → [13]  12 → [13,12]
2 → [13,12,2]              3 → [13,12,2,3]           * → 弹 2,3 算 6 → [13,12,6]
/ → 弹 12,6 算 2 → [13,2]   - → 弹 13,2 算 11 → [11]
```

🕷 官方点名的坑：**减法和除法的操作数顺序**——弹出顺序是"右操作数先出"，`a - b` 必须是 `次弹出的 - 先弹出的`（13 - 2 而不是 2 - 13）。错误输入的四类防御：坏 token、操作数不足两个、除零、**结束时栈里不是恰好一个数**。

## 6. 循环遍历队列的正确姿势（🕷 官方陷阱）

```cpp
// ❌ 错：dequeue 让 size 不断缩小，i 却在涨——只处理一半
for (int i = 0; i < q.size(); i++) { process(q.front()); q.pop(); }   // 1,2,3 只处理到 2 个就停

// ✅ 对：先把长度存下来
int n = q.size();
for (int i = 0; i < n; i++) { process(q.front()); q.pop(); }

// ✅ 对：经典 while 排干
while (!q.empty()) { process(q.front()); q.pop(); }
```

"边遍历边改变长度"是容器循环的第一戒（对 vector 的 erase 同理——stage2 模块 11 链表会再次遇到它）。

## 7. 常见误区清单

1. `std::stack::pop()` 不返回值——取值要 `top()`，二连写
2. range-for 遍历 stack/queue 编译不过（设计如此，不是你缺头文件）
3. `for i < q.size()` 边删边遍历——只处理一半
4. 后缀求值 `-` `/` 的操作数顺序搞反
5. 结束时不检查"栈里恰剩一个数"——坏输入静默给错答案
6. 官方库大写 `Stack`，std 小写 `std::stack`——混写编译错

## 8. 与超算比赛的联系

- **函数调用栈就是栈**：递归深度爆栈（stack overflow）是 DFS 类赛题的经典死法——"栈"不只是数据结构，是内存区域
- Graph500 的 BFS（HelloHPC 第 8 题）核心就是**队列驱动 frontier 扩张**；大规模图算法里队列的批量换块设计直接影响 TEPS
- 任务调度器（Slurm 的等待队列）本质是带优先级的队列（第 10 模块堆的前身）
- 后缀求值的"状态机 + 栈"模式在赛题的**输入解析**里反复出现
