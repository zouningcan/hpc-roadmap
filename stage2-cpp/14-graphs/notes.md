## 0. 一句话定位

图 = 顶点 + 边，**没有入口、没有层级**——链表和树都是它的特例。三件套问题：怎么存（表示）、怎么走（遍历）、怎么找最短（BFS/Dijkstra/A*）。

## 1. 定义与词汇表

`G = (V, E)`：顶点（vertex/node）集合 + 边（edge）集合。

| 术语 | 含义 |
|------|------|
| 路径 path | 依次相邻的顶点序列 |
| 环 cycle | 起点=终点的路径 |
| 路径长 | 边数（带权图里是**权重和**） |
| 相邻 adjacent | 共享一条边 |
| 可达 reachable | 存在路径 |
| 自环 loop | 指向自己的边 |
| 完全图 | 两两都有边 |
| **稀疏 vs 稠密** | 边数远小于 / 接近 n² |

变体：**带权**（边有数值）/无权；**有向**（箭头单行）/无向；**连通**（两两可达）/不连通。

## 2. 两种存法（官方核心结论）

### 邻接表（adjacency list）

每个顶点挂一个邻居列表（链表或哈希表）：

- 稀疏图空间 **O(n+E)**，列某点的 k 个邻居 O(k) ✅
- 稠密图退化 O(n²)、查询"边在不在"要扫链 ❌

### 邻接矩阵（adjacency matrix）

n×n 格子，`(i,j)` 存边（bool/权重）：

- **O(1)** 插边、查邻 ✅
- 恒定 **O(n²) 空间**（无向图还存两份）；列 k 个邻居要**扫一整行 O(n)** ❌

> **官方原话结论："稀疏图用邻接表，稠密图用邻接矩阵。"** ——真实世界的图（社交网络、网页链接）几乎全是稀疏的，所以邻接表（及它的 HPC 变体 CSR）是绝对主流。

std 实现参考（官方 BasicGraph 的等价物）：

```cpp
std::unordered_map<std::string, std::vector<std::pair<std::string,int>>> g;
g["u"].push_back({"v", 3});      // u → v，权重 3
```

## 3. 两大遍历：DFS 与 BFS

| | DFS 深度优先 | BFS 广度优先 |
|---|---|---|
| 策略 | 一条路走到黑，撞墙回溯（模块 07 回溯同款） | 一层一层向外扩 |
| 数据结构 | **栈**（或递归） | **队列** |
| 找到的路径 | **某条**路径（不一定最短） | **无权图的最短路径**（层级=距离） |

BFS 的队列驱动 = 模块 03/12 两次埋的伏笔兑现；DFS 的"回溯+visited 标记（面包屑）"= 模块 07 迷宫。

## 4. Dijkstra：带权图的单源最短路

**BFS 只会数边数；Dijkstra 数权重和**——官方例：直边 A→H 花 18，绕路 A→I→G→H 总共才 6，**绕路赢**。

**三件套机制**：

1. `dist[]`：起点 0、其余 ∞（ tentative 试探值）
2. **贪心选取**：每轮挑**未访问**中 dist 最小的点
3. **松弛（relaxation）**：处理它时，对每个未访问邻居尝试 `dist[邻居] = min(dist[邻居], dist[当前]+边权)`

处理过的点**打上 visited 永不回头**——这正是一切的前提：**负权边会打破它**（处理过的点本可能因负边变得更便宜，但 Dijkstra 不回头）。要负权 → Bellman-Ford（O(n³)，负环直接无解）。

**官方追踪表**（源 A）：A→I 1；A→I→E 3；A→I→G 4；A→I→G→H **6**；A→B 5。

### 🕷 "选最小"的实现四方案（官方深挖的工程细节）

优先队列看似天选，但**降值更新**（邻居被松弛后要把堆里旧记录改小）很贵：

| 方案 | 复杂度 | 评 |
|------|--------|-----|
| 删旧插新 | 每次 O(n log n) | "clearly absurd" |
| **惰性重复**（允许堆里有多份，弹出时验旧丢掉） | O(n² log n) | 课程采用版 |
| 斐波那契堆 | O(E + n log n) | 超纲 |
| **无序数组扫最小**（Dijkstra 原始版） | **O(n²)** | 简单粗暴常胜 |

**教训**：直觉的数据结构未必最优——**"更新优先级"这个操作的代价**决定了全局。

## 5. A*：Dijkstra 的导航版

优先级 = `已走代价 + h(当前)`（启发函数估计到终点的剩余距离）——**朝着目标"推一把"**。

- 前提：**已知终点** + 有办法估计剩余距离（地图可以直线距离；"找隐藏值"不行）
- **可采纳性（admissible）**：h **永不高估**真实剩余——否则最优性丢失
- 只求**到单点**的最短路（Dijkstra 是到全部）
- 会稍微"绕开再回来"——好事（上高速匝道的比喻：先背离再全速）
- 探索量对比：**BFS 最多 → Dijkstra 圆形扩散 → A* 最少直达**

**选择口诀**：无权最短 → BFS；带权全图 → Dijkstra；带权+已知终点+有好启发 → A*。

## 6. 拓扑排序（topological sort）

把**有向无环图**排成序列：j 只能在"所有指向它的点"之后出现。应用：任务依赖（先买面粉后烤饼干）、课程先修。

🕷 两个官方要点：① 拓扑序**不是图里的路径**（只是满足约束的排队）；② **有环则无解**——实现里循环结束还有点没排上 = 报错"有环"。

## 7. 常见误区清单

1. BFS 找带权图最短路——它只认边数
2. Dijkstra 用在负权图——visited 不回头，答案错；换 Bellman-Ford
3. A* 的启发高估——可采纳性破灭，路径不再保证最短
4. 稠密图硬上邻接表 / 稀疏图硬上矩阵——都反着官方结论
5. 忘 visited 标记——环上无限循环（模块 07 面包屑同款）
6. 拓扑序当路径验证——它只保证依赖顺序

## 8. 与超算比赛的联系

- **Graph500（HelloHPC 第 8 题）= BFS + SSSP 的大规模并行版**：官方参考实现正是 BFS（层同步 frontier）与 SSSP（类 Dijkstra）；调 MPI 进程/线程绑核冲 TEPS 的前提是懂算法本身
- **HPC 的图表示 = CSR**（压缩稀疏行）：邻接表的"数组化"（offset + edges 两个数组）——**零指针、缓存友好、可分块并行**，是稀疏结论在超算上的终极形态
- Dijkstra 的"惰性重复堆"方案在并行 SSSP（Δ-stepping）里仍是主角
- A* 的启发式思想 = 优化里的 branch-and-bound 剪枝（模块 07 C3 的通用化）
- 拓扑排序 = 编译/任务调度的依赖分析——Slurm 处理作业依赖的同款骨架
