# 模块 10（stage2）参考答案

## A1

结构性：**完全二叉树**（层满、最底层左对齐无洞）；有序性：**父 ≤ 子**（minheap）。完全性 ⇒ 层序遍历**恰好连续填满数组**——没有空洞就没有浪费，下标即可编码整棵树的形状。

## A2

左孩子 `2i+1`；右孩子 `2i+2`；父 `(i-1)/2`（整数除法）；最后一个非叶 `n/2 - 1`。

## A3

堆顶位置只能由"当前最小"占据，直接放新元素会顶掉它；且放顶破坏有序性。尾部是**唯一**追加后仍保持完全树的位置——先进场保结构，再用上浮修复顺序（一次只修一个性质，问题变小）。

## A4

与**较小**的孩子交换。若与较大孩子换：新父可能仍大于另一个（较小的）孩子——有序性当场违反。

## A5

| | 最好 | 最坏 |
|---|---|---|
| enqueue | O(1) | O(log n) |
| dequeue | O(1) | O(log n) |
| peek | O(1) | O(1) |

dequeue 最好：尾部替补的值比两个孩子的**较小者**还小——下沉一步（甚至零步）就位；这与堆多大无关。

## A6

heapify 自底向上下沉：**约一半节点是叶子（下沉 0 步）**，四分之一最多沉 1 步……只有极少数节点靠近根有 log 级高度。总代价 Σ(高度 h 的节点数 × h) = O(n)。乘法陷阱：把"单次最坏 O(log n) × n/2 次"当总复杂度——**忽略了每次操作时结构的真实状态**；求和必须逐项用真实代价。

## A7

是合法 minheap：验证 i=0: 2≤5,2≤3；i=1: 5≤9,5≤6；i=2: 3≤7 ✅。但数组**不是有序的**（5 在 3 前面）——堆只承诺"父不大过子"，**兄弟之间没有任何约束**。

## B1 参考（关键中间态）

enqueue 序列后的数组：`1 3 8 5 4 9`（1 从尾部一路浮到顶）。
第一次 dequeue：取 1，**尾部 9 替补到根** → 与较小孩子 3 换 → 与 8 换 → `3 4 8 5 9`。
第二次 dequeue：取 3，尾 5 替补 → `4 5 8 9`。
手算诀窍：**替补永远来自尾部**，路径永远"和较小孩子换"。

## B2 参考

实现见讲义第 4 节两个函数 + 类骨架。正确性预言：**全部出队序列单调不减**（每次取的都是当前最小）——这比抽查强得多。

## B3 参考现象

100 万元素：heapify 明显快于逐插入（约 2–3×，量级差异没理论那么夸张是因为常数，但方向一致）；**交换计数**更纯粹：heapify 的交换总数 ≈ O(n)，逐插入 ≈ O(n log n)——n 增大比值持续拉开，实测曲线直接画出两个阶级。

## B4 参考

`std::priority_queue<int>` 默认是**大顶堆**（less）；配 `greater<int>` 才是小顶。行为与 MiniHeap 一致（随机序列出队均为升序）。

## C1 参考

原地堆排序：
```cpp
heapify(v);
for (int end = v.size() - 1; end > 0; end--) {
    std::swap(v[0], v[end]);       // 当前最小沉到已排序区头部（升序排尾）
    down(v, 0, end);                // 堆范围缩小 1
}
```
优势：**O(1) 额外空间**（不造新数组、不递归）——vs 归并的 O(n) 辅助。四算法表中它与归并同阶、常数略大，但空间最优。

## C2 参考现象

全排序 vs 小顶堆流式：性能同数量级或堆略优；**决定性差别在内存**——堆解法只驻留 k=20 个数，流式处理**单遍扫描**、无需全量驻留。对超出内存的数据（日志流、分布式分片）这是从"做不了"到"做得了"的质变；map-reduce 的 Top-K 合并阶段用的正是这个思路。

## C3 参考现象

短作业优先（SJF）的**平均等待时间显著低于 FIFO**：FIFO 下一个大任务堵住后面所有小任务；SJF 让小任务先走，几乎无人久等（代价：大任务等待方差变大——公平与效率的经典权衡）。这正是 CPU/打印机调度理论的第一课，堆是它的高效实现。
