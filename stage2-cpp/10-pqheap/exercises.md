# 模块 10（stage2）练习：优先队列与二叉堆

> 分层：A 概念 / B 动手 / C 挑战。🕷 = 高频易错。
> 堆题的规矩：**先手画数组与树的对应**，再动手。

## A 概念题

**A1** 二叉堆的两性质？为什么"完全性"让它能平铺进数组？
*考察点：完全二叉树 + 父≤子；无空洞 → 层序连续存储。*

**A2** 0 起下标：节点 i 的左孩子、右孩子、父、最后一个非叶的下标公式各是什么？
*考察点：2i+1 / 2i+2 / (i-1)/2 / n/2-1。*

**A3** 为什么新元素必须从**数组尾部**进场再上浮，而不能直接放堆顶？
*考察点：放顶破坏完全性；尾部进场 = 唯一保持完全树的插入位。*

**A4** 🕷 minheap 的 percolateDown 要和哪个孩子交换？换错了会怎样？
*考察点：较小者；换大的会立即违反父≤子。*

**A5** enqueue/dequeue/peek 的最好与最坏复杂度？dequeue 最好 O(1) 是怎么发生的？
*考察点：表；替补根一步就位——与规模无关。*

**A6** 📍 heapify 为什么是 O(n) 而不是直觉的 O(n log n)？官方由此警告的"乘法陷阱"是什么？
*考察点：下层节点无高度可沉；逐项真实代价 ≠ 每项最坏 × 次数。*

**A7** `[2, 5, 3, 9, 6, 7]` 是不是合法 minheap 的数组？堆数组整体有序吗？
*考察点：验证父≤子（0-起验证 i 与 2i+1/2i+2）；父序≠排序序。*

## B 动手题

**B1（手画堆：三连操作追踪）** 从空 minheap 开始，纸上数组+树双画：
1. 依次 enqueue `5, 3, 8, 1, 4, 9`——每步标出上浮路径
2. dequeue 两次——每步标出"尾部替补 + 下沉路径"
3. 最后数组是什么？
用程序（B2）验证你的手算。
*考察点：堆操作的完整追踪——考试形态。*

**B2（完整实现：MiniHeap）**：
```cpp
class MiniHeap {
public:
    void enqueue(int x);          // push_back + percolateUp
    int dequeue();                // 取 h[0]，尾补根，percolateDown，pop_back
    int peek() const;             // h[0]
    int size() const;
private:
    std::vector<int> h;
    void up(int i);
    void down(int i, int n);
};
```
验证：B1 的序列 + 随机 10 万元素全部入队再全部出队，输出应**单调不减**。
*考察点：四个函数的完整落地；"出队序列有序"就是堆正确性的测试预言。*

**B3（heapify vs 逐插入）**：
1. 实现 `heapify(vector&)`：从 `n/2 - 1` 倒着 percolateDown
2. 对同一 100 万元素随机数组：heapify 计时 vs 逐个 enqueue 计时——量级差多少？
3. 📍 计数验证 O(n) vs O(n log n)：两种方式各统计**交换总次数**，比值随 n 增长怎么变？
*考察点：官方 bonus 的亲手复现；用交换计数代替计时更干净。*

**B4（std::priority_queue 对照）** 用 `std::priority_queue<int, std::vector<int>, std::greater<int>>`（小顶堆）重做 B2 的随机验证，确认行为一致。默认模板（不写 greater）是什么堆？
*考察点：标准库的堆适配器；默认大顶。*

## C 挑战题

**C1（堆排序）** 基于 MiniHeap 实现堆排序（入堆 + 出堆到数组），再实现**原地版**（heapify 后反复"根与尾交换 + 缩小范围下沉"）。两者复杂度同为 O(n log n)，原地版的优势是什么？与模块 08 的归并/插入放进同一张实测表里比一比。
*考察点：堆顶-尾交换的原地化技巧；四排序同台。*

**C2（Top-K：海量数据的前 K 名）** 100 万个随机数取最大的 20 个：
1. 全排序后切尾部（O(n log n)）
2. 20 大小的**小顶堆**流式处理（O(n log k)）：新数比堆顶大才入堆
两者计时对比。方法 2 为什么只需 k 大小的内存——这对"数据大到放不进内存"意味着什么？
*考察点：Top-K 堆解法；流式/有界内存——分布式日志分析的标准姿势。*

**C3（带数据优先队列：模拟打印队列）** `struct Job { int pages; int id; };` 按 pages 为优先级实现 `PriorityQueue<Job>`（模板或 pair 实现）。模拟官方场景：100 个任务（页数 1–500 随机）全部入队，依次出队打印（每页 1ms 计时），对比"先进先出"与"最短优先"两种策略的**平均等待时间**。
*考察点：优先级捆绑数据（ADT 的本义）；短作业优先为什么平均等待更优——调度理论的种子。*
