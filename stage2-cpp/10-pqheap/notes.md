## 0. 一句话定位

**优先队列**（按优先级出队的队列）+ 它的王牌实现**二叉堆**（藏在数组里的完全二叉树）。"插入和取最小都只要 O(log n)"——Dijkstra（模块 14）的引擎、堆排序的骨架。

## 1. 优先队列 ADT

= "把优先级和数据捆在一起"的队列：**优先级小的先走**（minheap 约定）。

| 操作 | 语义 |
|------|------|
| `enqueue(value, priority)` | 入队（insert/add 同义） |
| `dequeue()` | 取出并删除**优先级最高**（值最小）者（deleteMin） |
| `peek()` | 只看不取 |

现实例子（官方）：**共享打印机**——按页数当优先级，1 页的小任务不该排在 500 页后面。🕷 不支持任意删除（代价 O(n) 且会破坏结构）——需要就换结构。

## 2. 二叉堆：两性质定义

1. **结构性**：**完全二叉树**——每层全满，唯独最底层**从左到右连续无空洞**
2. **有序性**（minheap）：**每个节点 ≤ 它的孩子们**（从而 ≤ 全部后代）

树词汇 prerequisite：节点/边/父/子/根/叶/左右孩子。**maxheap** 把 ≤ 反成 ≥。

**为什么完全性是宝藏**：没有空洞 → 可以**平铺进数组、零浪费**，还天然知道每个节点的位置。

## 3. 数组表示与索引算术（本讲核心机关）

n 个节点按层序从左到右住进 `vector`，下标 0 起：

| 关系 | 公式（0 起下标） |
|------|------------------|
| 节点 i 的**左孩子** | `2*i + 1` |
| 节点 i 的**右孩子** | `2*i + 2` |
| 节点 i 的**父** | `(i - 1) / 2`（整数除法） |
| **最后一个非叶** | `n/2 - 1`（heapify 的起点） |

不用指针、不用结构体——**下标算术就是树的形状**。堆高 = ⌊log₂n⌋，这是后面一切 O(log n) 的来源。

## 4. 两个核心操作：上浮与下沉

### percolateUp（入队用，siftUp/bubbleUp）

新元素**追加在数组末尾**（保持完全性），然后**只要比父小就和父交换**，一路浮到不比父小为止。

```cpp
void percolateUp(std::vector<int>& h, int i) {
    while (i > 0 && h[i] < h[(i - 1) / 2]) {     // 还有父 && 比父小
        std::swap(h[i], h[(i - 1) / 2]);
        i = (i - 1) / 2;
    }
}
```

### percolateDown（出队/建堆用）

取走堆顶（下标 0）后，把**最后一个元素搬到根**，然后与**较小的那个孩子**换着往下沉，沉到不大于孩子为止（沉错方向会破坏有序性——和模块 06 后缀求值的操作数顺序同款"方向敏感"）。

```cpp
void percolateDown(std::vector<int>& h, int i, int n) {
    while (true) {
        int smallest = i, l = 2*i + 1, r = 2*i + 2;
        if (l < n && h[l] < h[smallest]) smallest = l;   // 与较小孩子
        if (r < n && h[r] < h[smallest]) smallest = r;
        if (smallest == i) break;
        std::swap(h[i], h[smallest]);
        i = smallest;
    }
}
```

## 5. 复杂度表（官方）

| 操作 | 最好 | 最坏 |
|------|------|------|
| enqueue | O(1)（比父大，一步到位） | O(log n)（浮到顶） |
| dequeue | O(1)（根沉一层就位） | O(log n)（沉到叶） |
| peek | O(1)（就是 h[0]） | O(1) |

**两个 O(1) 的来源值得回味**：最好情况的 dequeue 发生在"替补根比孩子都小"——再大的堆也可能一步就位。**复杂度看的是最坏**（模块 05 的纪律）。

## 6. 建堆的两条路（含一个著名陷阱）

- **逐个插入**：n 次 enqueue，Σlog k = O(n log n)（Stirling 逼近的正式推导）
- **heapify（官方 bonus）**：对**后半的非叶节点**（从 `n/2-1` 倒着到 0）依次 percolateDown——表面上 n/2 次 × O(log n) = O(n log n)，**实际是 O(n)**：绝大多数节点在树的下层，根本**没高度可沉**

🕷 **官方警示的"乘法陷阱"**：结构尺寸在变化时，把"每次操作的最坏 × 次数"当复杂度可能严重高估——heapify 是著名反例。**求和要看每项的真实代价**，不是每项的最坏。

**堆排序**：n 次 enqueue + n 次 dequeue = O(n log n)（heapify 原地建堆版更优）。

## 7. 常见误区清单

1. 下标公式记错偏移（0 起是 `2i+1`；1 起才是 `2i`——刷题时两套约定都出现）
2. 下沉时和**较大**孩子换（minheap）——有序性立崩
3. 往堆顶放新元素再上浮——破坏完全性；**新元素必须在尾部进场**
4. heapify 从叶子方向开始或从 0 正着来——正确姿势是**从最后一个非叶倒着** down
5. 以为堆数组整体有序——只保证**父 ≤ 子**，兄弟之间无约束（层序 ≠ 排序序）
6. 在堆上做任意删除/查找——那是 O(n)，设计错误

## 8. 与超算比赛的联系

- **Dijkstra/A\***（模块 14、HelloHPC 无直接题但图赛题常见）靠堆把 O(V²) 降到 O(E log V)
- **堆 = 任务调度器的内核抽象**：Slurm 的排队就是带优先级的队列；操作系统的中断/进程队列同构
- **Top-K 问题**：海量数据里"前 K 大"用 K 大小的堆 O(n log k)——比全排序 O(n log n) 划算（日志分析常客）
- 数组化树**零指针、缓存友好**（模块 02 的连续内存优势在树身上的完美案例）——HPC 里"隐式数据结构"的代表作
