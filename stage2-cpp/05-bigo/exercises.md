## A 概念题

**A1** 化简并归类：
a) `3n² + 200n + 5000`
b) `n log n + n²/100`
c) `7 log n + 30`
d) `n/2 + n/3 + n/6`
e) `2ⁿ + n¹⁰⁰`
*考察点：丢系数、取最高阶项。*

**A2** 🕷 判断并说理：
a) 两个**先后执行**的 O(n) 循环，整体是 O(2n) = O(n)？
b) `for(i<n) for(j<=i)` 的三角形循环是 O(n²) 还是 O(n³)？
c) 一个函数先做 O(n log n) 的排序再做 O(n) 的扫描，整体？
*考察点：顺序相加、三角形求和、混合取最大。*

**A3** 🕷 这两个函数的复杂度差在哪？各自是多少？
```cpp
int sizeA(std::vector<int> v)  { return v.size(); }
int sizeB(std::vector<int>& v) { return v.size(); }
```
*考察点：传值拷贝把 O(1) 变 O(n)。*

**A4** a) 为什么"每次把 n 砍半"的循环是 O(log n)？b) 官方纠正的直觉错误是什么——O(log n) 在 O(1) 和 O(n) 之间的什么位置？
*考察点：2³⁰≈10亿→30步；log 贴地不是中点。*

**A5** 用外推表回答：某 O(n²) 算法在 n=10⁵ 时跑 1 秒，n=10⁶ 时大约跑多久？如果换成 O(n log n) 呢（用 n log n 增长外推）？
*考察点：平方 100×；线性对数约 20×。*

**A6** `v.push_back(x)` 偶尔要扩容搬移整个数组（单次 O(n)），为什么还说循环 push_back 建表是 O(n) 而不是 O(n²)？
*考察点：摊还分析——偶尔贵平均便宜。*

## B 动手题

**B1（复杂度实证台）** 实现四个函数并各在 n = 10⁵、2×10⁵、4×10⁵ 下计时（O(2ⁿ) 的 fib 用 n=25/27/29）：
```cpp
long long sumLinear(int n);        // 1+2+...+n，单循环
long long sumTriangle(int n);      // 嵌套 for(j<=i)
int countHalving(int n);           // while(n>1) n/=2
long long fibExp(int n);           // 朴素递归 fib
```
**先纸笔预测** n 翻倍时各自的时间比（1×/2×/4×/…），再实测对表。
*考察点：每条增长曲线在 stopwatch 上长什么样——把抽象和体感焊死。*

**B2（🕷 传值陷阱实测）**：
```cpp
int64_t sumByValue(std::vector<int> v)  { int64_t s=0; for(int x:v) s+=x; return s; }
int64_t sumByRef(const std::vector<int>& v) { 同样 }
// vector 大小 4000 万，各计时
```
两者 Big-O 都是 O(n)，实测差多少？差的这部分 Big-O 说了吗？——这印证了讲义第 7 节的哪句话？
*考察点：同阶不同常数；"HPC 活在 Big-O 丢掉的部分里"。*

**B3（求和恒等式验证）** 用 B1 的 sumTriangle 对比"直接公式 n(n+1)/2"的耗时，并数学证明两者结果恒等（正序+倒序相加的官方推导，自己写一遍）。
*考察点：恒等式推导；"换算法降阶"的最小案例。*

## C 挑战题

**C1（官方外推题风格：TSP）** 旅行商问题目前最好算法约 O(n²·2ⁿ)。已知 n=50 时需 4 天，估算：
a) n=64 需要多久？（提示：算 (64/50)² × 2¹⁴ 的量级）
b) 由此说明为什么 TSP 的大规模实例靠"等更快的计算机"没用，只能靠近似算法/剪枝。
*考察点：指数外推的绝望算术；战略上换路线的理由。*

**C2（降阶实战：重复检测三档）** 对含 10 万个随机 int 的 vector 判断"是否有重复"，写三版：
1. 嵌套循环 O(n²)
2. 先 sort（O(n log n)）再查相邻相等
3. unordered_set 一趟 O(n)
各实测耗时（1 版可缩到 1 万元素）。比值和理论阶对得上吗？第 3 版最坏情况是什么（提示：哈希冲突）？
*考察点：三阶级的真实差距；哈希的"平均"二字。*

**C3（分析你自己的代码）** 回到模块 04 B3 的频次统计程序：整体复杂度是多少（读入 + 每次 `freq[w]++` 的 map 操作 O(log n)）？如果换成 unordered_map 呢？用 10 万词实测两者的差距，并解释"理论只差一个 log，实测为什么接近/不接近"。
*考察点：map 操作进分析；log 因子在实测里的样子。*
