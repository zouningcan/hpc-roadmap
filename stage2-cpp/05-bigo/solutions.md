# 模块 05（stage2）参考答案

## A1

a) O(n²)　b) O(n²)（n² 压过 n log n）　c) O(log n)　d) **O(n)**（n/2+n/3+n/6 = n——系数花招）　e) O(2ⁿ)（指数碾压任何多项式）

## A2

a) 对。顺序执行是**加法**：O(n)+O(n)=O(2n)=O(n)。
b) **O(n²)**。内层执行 1+2+…+n = n(n+1)/2 次——三角形和的信号（系数 1/2 被丢掉）。
c) O(n log n)——混合取最大者，排序主导。

## A3

sizeA **O(n)**（传值：整份拷贝 vector 是隐藏的全量工作，拷贝压倒 size() 本身）；sizeB **O(1)**（引用直达，只读一个长度字段）。同一个"查长度"，参数写法决定阶级——分析必须**包含参数传递的成本**。

## A4

a) 每轮 n 减半，到达 1 需要 log₂n 轮；每轮 O(1) → 总 O(log n)。
b) 官方纠正：O(log n) **贴着 O(1)**，绝不是 O(1) 到 O(n) 的"中间一半"。10 亿规模只需 30 步——几乎不随规模变贵。

## A5

- O(n²)：n×10 → 时间 ×100 → 约 **100 秒**
- O(n log n)：n×10 → 时间 ×(10·log(10⁶)/log(10⁵)) ≈ ×(10×1.2) ≈ **12 秒**
外推纪律：先算规模倍数 k，再按阶级算 k、k²、k·(log 比值)。

## A6

摊还分析：扩容不是每次都发生——按**倍增**策略，n 次 push_back 的总搬移 ≤ 1+2+4+…+n < 2n，均摊每次 O(1)。关键在"偶发的大账单被之前的便宜均摊"。（对比：`insert(0)` 是**每次**都搬——无摊还可言，O(n²)。）

## B1 预测与实测对照

| 函数 | 阶 | n 翻倍时间比（预测） |
|---|---|---|
| sumLinear | O(n) | ≈ 2× |
| sumTriangle | O(n²) | ≈ 4× |
| countHalving | O(log n) | ≈ 1×（几乎不动） |
| fibExp | O(2ⁿ) | ≈ 2×，但基数巨大（n=29 已秒级） |

实测允许噪声（±10%），数量级对上即达标。fibExp 的 2× 是"每 +2 规模翻倍"——指数的本质。

## B2 参考现象

两者都 O(n)，实测通常差 **2–5×**（拷贝 4000 万 int 的内存带宽成本）。Big-O 对此**沉默**——它只管增长形状。印证讲义第 7 节：**同阶不同常数、HPC 活在 Big-O 丢掉的部分里**——传 const 引用是零成本习惯，收益却是一次完整拷贝。

## B3

公式版 O(1) vs 循环版 O(n)：大 n 下循环版线性涨、公式版测不出时间（纳秒级）。
推导：S = 1+…+n；倒序 S = n+…+1；逐列相加每列都是 n+1，共 n 列 → 2S = n(n+1) → S = n(n+1)/2。∎

## C1

a) (64/50)² ≈ 1.64；2⁶⁴⁻⁵⁰≈2¹⁴ ≈ 16384 → 总慢约 27000 倍：4 天 × 27000 ≈ **295 年**（官方口径 194 年，量级一致——外推题看量级）。
b) 指数爆炸下，硬件提速 100 倍只把 n 极限推几个——**摩尔定律救不了指数**，出路只有近似算法（遗传/模拟退火）、剪枝（分支定界）或接受局部最优。这是"战略换路线优先于战术磨常数"的极端案例。

## C2 参考现象（10 万元素量级）

| 版本 | 阶 | 典型耗时 |
|---|---|---|
| 嵌套循环 | O(n²) | 秒级~分钟级（1 万元素） |
| sort+相邻 | O(n log n) | 毫秒级 |
| unordered_set | O(n) 平均 | 更快但与上者同数量级 |

对表：n² 与 n log n 差 ~n/log n ≈ 6000 倍（实测因缓存等因素小一些）；2 与 3 只差一个 log 因子（≈17×），且哈希函数本身有常数，实测可能只差 2–5×。
第 3 版最坏：**所有键哈希冲突**（退化成链式扫描 O(n²)）——"平均 O(1)"的"平均"二字是免责声明，恶意构造的输入能打爆它（这也是哈希种子随机化的由来）。

## C3 参考

map 版：读 n 个词 + n 次 O(log n) 自增 → **O(n log n)**；unordered_map 版平均 **O(n)**。
实测：10 万词下两者常差 2–4×（不是理论的 ~17×），原因：词表去重后独立键只有几千个——**n 应取"不同词数"而非总词数**，log 因子作用在小集合上差异缩小；加上 map 的缓存友好（连续树节点分配）补回一部分。教训：理论要**用对 n 的定义**再对实测。
