# 模块 05（stage2）：Big-O 与算法分析

> **来源**：Stanford CS106B 2026 夏 L7《Big-O and Algorithmic Analysis》
> https://web.stanford.edu/class/archive/cs/cs106b/cs106b.1268/lectures/07-bigo/
> 本模块把前几讲实测过的"338×""set 飞快"翻译成**正式语言**，并给出 HPC 视角的关键补充：Big-O 之后的世界。

## 0. 一句话定位

Big-O 描述**工作量随输入规模增长的"种类"**——不看秒数、不看精确次数，只看增长曲线的**形状**。选对复杂度是战略，常数优化是战术；HPC 两个都要，但顺序不能反。

## 1. 为什么不用"掐表"和"数指令"

官方否决两种直觉方案：

- **掐表**：要求同机器、同测试用例、同架构、无后台干扰——四条都不可控（stage1 模块 07 的 hyperfine 尽量控制了这些，但跨机器比较仍无意义）
- **数指令**：`i++` 到底算一次赋值还是一次赋值+一次算术？不同指令周期不同、编译器还会优化——官方原话"数指令是徒劳的（a fool's errand）"

于是抽象一层：**只谈增长的数量级**。

## 2. Big-O 三步法（官方处方）

1. **假设输入任意大**（n → ∞，小数据的差异不重要）
2. **找执行最多的语句**，数它的执行次数（关于 n 的表达式）
3. **丢掉常数系数、只留最高阶项**

复杂度阶级表（官方例题全收录）：

| 表达式 | Big-O | 名字 |
|---|---|---|
| `n + 4n³ + 2n² + 1055` | O(n³) | 立方 |
| `(1/6)n² + 1000n` | O(n²) | 平方 |
| `log n + n` | O(n) | 线性 |
| `n log n + n` | O(n log n) | 线性对数 |
| `log n + 40` | O(log n) | 对数 |
| `6n + 2ⁿ` | O(2ⁿ) | 指数 |
| `5` | O(1) | 常数 |

🕷 写法纪律：常数一律写 **O(1)**，不写 O(10)——"1"代表"与 n 无关"，不是"一次"。

## 3. 代码小片段速判（官方 vignettes）

| 代码 | 复杂度 | 为什么 |
|---|---|---|
| `swap(a, b)` | O(1) | 与 n 无关 |
| `vectorSum`（单循环） | O(n) | 最热语句跑 n 次 |
| **两个先后**单循环 | **仍是 O(n)** | 2n 丢系数——Big-O 看"种类"不看快慢 |
| 嵌套循环 | O(n²) | O(n) 的内层跑了 n 遍 |
| 🕷 `vectorSize(Vector v)` **传值** | O(n) | **拷贝 vector 抢占了全部工作量** |
| `vectorSize(Vector& v)` 传引用 | O(1) | 不拷贝，只查个头字段 |
| `v.push_back` 循环建表 | O(n) | 尾部追加（摊还 O(1)） |
| 🕷 `v.insert(0, i)` 循环建表 | **O(n²)** | 1+2+…+n 次搬移——模块 02 的 338× 实测正式归档 |

**摊还（amortized）补充**：`push_back` 偶尔触发扩容是 O(n)，但均摊到每次是 O(1)——"偶尔贵、平均便宜"是动态数组的核心性质。

## 4. 关键求和恒等式：1 + 2 + … + n = n(n+1)/2

官方推导：正着写一遍、倒着写一遍，上下相加——每个位置都是 n+1，共 n 列，所以 2S = n(n+1)。

**肌肉记忆：见到 Σi 立刻反应 O(n²)**。递归树画出来是三角形/楼梯形的，同理。

## 5. 增长的杀伤力：外推表

| 复杂度 | n=50 花 100ms，则 n=100 花 | 更远的下场 |
|---|---|---|
| O(n) | 200ms（2×） | 线性可控 |
| O(n²) | 400ms（4×） | **n=100 万 ≈ 463 天** |
| O(2ⁿ) | 100ms@5 → **38.8 天@30** | 旅行商（TSP，最好已知 O(n²2ⁿ)）：50 城 ≈ 4 天，**64 城 ≈ 194 年** |

这张表是"为什么必须先换算法再谈优化"的全部理由。

## 6. 对数的直觉：每次砍半

```cpp
while (n > 1) { n = n / 2; }   // 循环体 O(1) → 整体 O(log n)
```

**2³⁰ ≈ 10 亿**——10 亿规模的数据，砍半只需 30 步。所以 O(log n) 直观上"**贴着 O(1)**"，绝不是"O(1) 到 O(n) 的一半"（官方特意纠正的直觉错误）。二分查找、平衡树（stage3）、快排递归深度都是它。

## 7. HPC 补充视角：Big-O 之后的世界（本仓库加餐）

Big-O 说的是**增长形状**，故意丢掉了常数和访存模式——而**超算比赛恰恰活在被丢掉的那部分里**：

1. **同 Big-O 差 10×**：行优先 vs 列优先遍历（模块 02 实测）都是 O(n²)，但缓存让它们差几倍——优化常数与访存是 HPC 的主战场
2. **摊还的实战**：动态数组预扩容策略（翻倍 vs 加一）直接决定 HPC 内核里建表的开销
3. **复杂度阶级是天花板**：先保证算法是 O(n log n) 再谈向量化——用 SIMD 加速 O(n²) 的冒泡，不如换 O(n) 的计数（HelloHPC 第 3 题位矩阵正是"换思路降阶"的案例）

**顺序纪律：先选对阶级，再磨常数。** 反过来做是无底洞。

## 8. 常见误区清单

1. 两个先后 O(n) 循环写成 O(2n) 再报 O(n²)——顺序执行是**加**不是乘
2. 常数写 O(10)、对数纠结底数（log₂n 与 log₁₀n 只差常数因子，统一写 log n）
3. 把 O(log n) 想成"O(1) 和 O(n) 的中间一半"——它是贴地的
4. 传值大容器不自觉引入 O(n)——分析**包含**参数拷贝
5. 见到嵌套循环无脑 O(n²)——内层次数依赖什么？三角形循环（j<=i）也是 O(n²) 但系数减半
6. 用掐表数纳秒代替分析——机器噪声淹没信号

## 9. 与超算比赛的联系

- 每道赛题的第一问都是"当前实现是什么复杂度、理论下界是什么"——差距即优化空间
- HelloHPC 第 3 题（位矩阵）：朴素 O(N³/64) → 位并行与向量化降常数；第 5 题（Calculation）：`std::pow`/三角函数的数学等价变换直接降阶
- 外推表 = 赛前估时：知道 O(n²) 在 n=10⁶ 要 463 天，就不会把周末浪费在错误算法的调优上
- stage1 模块 07 的 profiling 找热点 + 本模块的复杂度分析 = 优化的完整决策链
