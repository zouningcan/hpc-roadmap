> 树 = 链表 + 一个指针（left/right 双叉）；BST = 有序的树；Huffman = 堆+树的合体应用。

## 0. 一句话定位

模块 11 的节点只有 `next`，本模块的节点有 `left` 和 `right`——**结构一小步、能力一大步**：对数级查找（BST）、天然排序输出（中序）、数据压缩（Huffman）全部从中长出来。

## 1. 树的骨架：TreeNode 与词汇表

```cpp
struct TreeNode {
    int value;
    TreeNode* left;
    TreeNode* right;
};
// root 指针是树的唯一入口（同链表的 head）
```

**词汇表**：根（root，无父的顶点）、叶（leaf，无子的节点）、高度（height：从根往下数的最长路径）、深度（depth：从某节点往根数的距离）。读指针链：`root->left->right->value` = 解引用 → 取 left → 再解引用 → 取 value（**每个箭头一次解引用**）。

## 2. 四种遍历（本模块的基本功）

深度优先三兄弟（递归结构一模一样，只差**访问语句的位置**）：

```cpp
void traverse(TreeNode* node) {
    if (!node) return;
    // 【前序】此处打印 node->value     —— 根-左-右
    traverse(node->left);
    // 【中序】此处打印                 —— 左-根-右
    traverse(node->right);
    // 【后序】此处打印                 —— 左-右-根
}
```

第四种：**层序（level-order）**用**队列**逐层横扫（队列驱动 = 模块 03 埋的 BFS 伏笔）。

**官方例题答案**（树：23 → 左 11（右子 19）、右 57（右子 89，其子 81/99））：

| 遍历 | 输出 |
|------|------|
| 前序 | 23, 11, 19, 57, 89, 81, 99 |
| 中序 | **11, 19, 23, 57, 81, 89, 99**（注意：BST 的中序 = 升序序列！） |
| 后序 | 19, 11, 81, 99, 89, 57, 23 |

**遍历的三大应用**（L22）：前序 = DOM 的 `getElementById` 搜索；中序 = BST 按序处理；后序 = `forestFire` 释放整棵树（**先烧孩子再烧自己**——先序删会解引用已删节点）。

## 3. BST：给树立规矩

**有序性**：左子树全 < 根 < 右子树全（对每个节点递归成立）。

### 查找/插入

```cpp
void bstInsert(TreeNode*& root, int data) {     // 📍 又见 Node*&！
    if (!root) { root = new TreeNode{data, nullptr, nullptr}; return; }
    if (data < root->value) bstInsert(root->left, data);
    else                    bstInsert(root->right, data);
}
```

🕷 **为什么必须 `TreeNode*&`**（官方原题）：插入发生在"**空指针的位置**"——递归到 `root->left` 为 null 时，要写的正是**那个指针本身**；按引用传，`root` 就是父节点 left 字段的别名，`root = new...` 直接挂上新节点。

### 删除三案例（L22 核心）

| 案例 | 处理 |
|------|------|
| 叶子 | 直接剪掉 |
| 单孩子 | 孩子上位顶替（孙辈跟随） |
| 双孩子 | 用**左子树的最大值**替换本节点值，再**递归删除左子树里那个最大值**（官方以左max为标准；右min也对，但课程统一） |

### 复杂度表

| 操作 | 最好 | 最坏 | 平均 |
|------|------|------|------|
| search/insert/delete | O(1) | **O(n)** | O(log n) |

🕷 **最坏 = 退化成链表**：按 1,2,3,...,n 插入，每个都往右钻——树成了一条腿，查找 O(n)。**平均 O(log n) 的前提是树"长得匀"**。

### 自平衡树（一句话开启新世界）

AVL、红黑树、2-4 树：通过旋转等手段保证**左右子树高度差 ≤ 1**，把最坏钉死在 **O(log n)**——**std::map/set 的内部就是它们**（模块 04 的"有序版飞快"至此有了解释：每次操作走树高 log n）。代价：节点更大（int + 两个 8 字节指针 = 20 字节/节点 vs 数组 4 字节）、指针跳转缓存不友好——又一笔空间/缓存换时间的买卖。

## 4. 树的内存纪律（L22 补遗）

- `forestFire(root)`：后序递归 delete 全树；delete 后**把指针置 nullptr**（悬垂防御）
- 官方 debug 题：一个 `height()` 忘判空根——**空树直接段错误**
- 空树处理三流派：约定不传空 / 返回 `INT_MIN` 之类哨兵 / 抛异常——各有代价，**函数合同里写清楚**最重要

## 5. Huffman 编码（L23：堆 + 树的合体大招）

**动机**：压缩 = 利用冗余。ASCII 定长 8 位——但"字符生而不平等"：英文文本里 e 满地都是、q 罕见（摩尔斯电码 1850 年代就想通了：e 一个点、q 很长）。

**官方数字阶梯**（"happy hip hop"，13 字符）：

| 方案 | 位数 | 占比 |
|------|------|------|
| ASCII 定长 8 位 | 104 | 100% |
| 7 字符定长 3 位 | 39 | 38% |
| **变长（按频次）** | **34** | 33% |

**前缀自由码（prefix-free）**：任何字符的编码都不是另一个的前缀——解码**无需分隔符**也不歧义。用树实现：**字符只放叶子**，左 0 右 1，编码 = 根到叶的路径。字符全在叶子上 ⇒ 前缀性质自动成立（一个码是另一码前缀 ⟺ 一者在另一者的路径上 ⟺ 一者是另一者的祖先 ⟺ 不是叶子）。

🕷 **反转认知**：BST 里失衡是坏事，Huffman 里**失衡是追求**——高频字符挂得浅（码短）、低频挂得深（码长）。

**建树算法**（n 个不同字符，n−1 次合并）：

1. 统计每个字符频次作为权重
2. 每个字符造一个叶子 → 一片**森林**
3. 循环：**取出权重最小的两棵树**，合并到新根下（权重相加），插回森林
4. 森林剩一棵树 → 完成（根的权重 = 总字符数）

"取最小两棵" = **优先队列**的活——模块 10 的堆在这里兑现（课程把实现留给 Assignment 7）。**平局任意破**：不同选择生成不同但**同样最优**的树——所以编码端必须把树（或码表）**随数据一起打包**，解码端重建成同一棵树。

**解码**：从根出发，逢 0 走左逢 1 走右，**踩到叶子就输出字符并回根**。官方例：`111100110101111` → "yippy"。

## 6. 常见误区清单

1. 忘了"**BST 中序 = 升序**"这个免费性质（判断 BST 合法性/调试神器）
2. bstInsert 忘 `&`——新节点挂不上（NULL 副本上写 = 白写）
3. 双孩子删除直接删——必须先找左子树 max 顶替再递归删
4. 前序释放树——烧了自己再找孩子（悬垂）；释放用后序
5. Huffman 把字符放内节点——前缀性质破灭，解码歧义
6. 编码解码用不同的树——平局破法不同，码就不同；树必须随数据打包
7. 以为 BST 平均 O(log n) 无条件成立——退化输入就是链表

## 7. 与超算比赛的联系

- **std::map/set = 红黑树**——比赛代码里每个 map 操作都在走树高；换成 unordered（哈希，下一模块）的取舍判断由此而来
- **递归树高 = 栈深 O(log n)**：树的递归天生安全（对比链表的 O(n) 递归）——但自平衡被破坏时可退化
- **Huffman 思想 = 按频次分配资源**：数据压缩在赛题数据集分发、日志归档里直接可用；更深一层，"变长编码+前缀性质"是信息论的入口
- 层序遍历的队列驱动 = 图 BFS 的同构（模块 14 直通票）
