# 模块 08（stage2）参考答案

## A1

| 算法 | 最坏 | 最好 | 比较 | 移动 |
|------|------|------|------|------|
| 选择 | O(n²) | **O(n²)** | 全扫（高斯和） | 每轮恰一次交换（最少） |
| 插入 | O(n²) | O(n) | 可提前停 | 挪移频繁（peach 版减半写） |
| 归并 | O(n log n) | O(n log n) | 每层 n 次 | 全量进出辅助数组 |

## A2

选择排序每轮必须**扫完整个未排序区**才能确定最小值——输入已经有序也改变不了扫描结构。插入排序对**已就位**的元素只做一次比较就停（v[gap-1] > peach 不成立立即落位）——有序输入每轮 O(1)，整体 O(n)。

## A3

每层：当前层所有归并的总工作量 = 该层元素总数 = n（每元素一次比较一次写）。层数：每次对半分，从 n 到 1 需要 log₂n 次切割 → log₂n + 1 层。总 = n × (log₂n + 1) = **O(n log n)**。

## A4

- 仓库冰箱（选择）：**搬移贵、比较便宜**——多看几眼无妨，搬运要最少。数据巨大/写代价高（数据库页、嵌入式 Flash）时选它
- 跑步排名（插入）：**比较贵、挪移便宜**——比较一次定胜负，挪位不心疼。比较函数复杂（自定义对象排序）且数据接近有序时选它

## A5

取左保证**稳定性**（相等元素保持原相对顺序）——左边代表"更早出现"。取右边则相等元素次序反转，稳定语义破坏：多关键字排序（先按 A 排再按 B 排，希望 B 相同时保持 A 序）会得到错误结果。

## B1 参考

骨架见讲义第 1–3 节；mergeTwo 要点：辅助数组 + 双指针 + 两守卫（`i > mid` / `j > hi`）+ 拷回。用 `std::sort` 当预言机是"**拿可信实现验证自己的实现**"的标准姿势。

## B2 参考现象

n×10：选择/插入约 ×100（O(n²)），归并约 ×13–15（10 × log 比值 ≈ 10×1.17）——与阶级预测吻合；绝对值与官方表同量级（机器差异 ±2× 正常）。

## B3 参考现象

1. 已排序 100 万元素：插入排序**毫秒级**（每轮一次比较即停，O(n)）——比它在随机输入上快几个数量级
2. 逆序：最坏形态，每轮拖到底（O(n²)），百万级分钟起步（可降到 10 万元素测）
3. 选择排序两组耗时**几乎相同**——它对输入顺序免疫

## B4 参考现象

n ≤ 50~100 区间插入领先（递归调用的常数开销 > 阶级优势）；n 到几百后归并反超并拉开。交叉点位置依实现与机器浮动——**测出来的**，不是背出来的。

## C1 参考

```cpp
void hybridSort(std::vector<int>& v, int lo, int hi) {
    if (hi - lo < CUTOFF) { insertionSortRange(v, lo, hi); return; }
    ...
}
```
阈值取 B4 交叉点（约 30–100），混合版通常比纯归并快 10–30%。曲线呈浅 U：阈值太小递归开销回潮、太大插入的 O(n²) 侵蚀——**调参 = 在两种开销间找谷底**，这正是 std::sort introsort 的日常。

## C2 参考

```cpp
for (int width = 1; width < n; width *= 2)
    for (int lo = 0; lo + width < n; lo += 2 * width)
        mergeTwo(v, lo, lo + width - 1, std::min(lo + 2*width - 1, n - 1));
```
结果与递归版一致；耗时通常略优（省掉递归调用与栈帧）；本质：**把"分"的过程改成从叶子直接合并**，宽度 1→2→4→… 循环代替了递归下降。

## C3 参考

1. 稳定归并（相等取左）：同分玩家保持输入顺序 ✅
2. 选择排序反例：`[("A",5), ("B",3), ("C",5)]` 按分排——第一轮把 B 换到位置 0 时，A 与 C（同分 5）顺序仍是 A...C；再构造 `[("B",3),("A",5),("C",5)]`：第一轮 B 与 A 交换 → `[A? ...]` 具体：min 搜索把索引 0 的 B 换走时 A、C 顺序不变——真正的不稳定出现在**交换跨越相等元素**时：`[("A",2),("B",2),("C",1)]`：第一轮 C 换到 0 位，A 与 B 顺序仍 A,B……标准反例：`[("a",5),("b",5),("c",0)]` → 第一轮 c 与 a 交换后 a,b 相对序保持；换 `[("b",5),("a",5),("c",0)]`：c 与 b 交换 → `[c, a, b]` → 第二轮 a,b 本来 b 在前，结果输出 a 在 b 前——**同分元素顺序反转** ✗（动手跑一遍即可看到）
3. `std::stable_sort` 与你的稳定归并行为一致；教训：**需要稳定性时选错算法 = 结果错误**，不是慢一点的问题
