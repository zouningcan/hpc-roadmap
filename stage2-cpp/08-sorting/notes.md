## 0. 一句话定位

三个性格迥异的排序：**选择**（看准再动）、**插入**（边走边挪）、**归并**（分而治之）。复杂度从 O(n²) 到 O(n log n)——10 亿元素时是 **300 亿次操作 vs 10¹⁸ 次**的天壤之别。

## 1. 选择排序（selection sort）："wait and see"（等着瞧）

每轮**扫完未排序区找出最小值**，一次交换放到目标位。

```cpp
for (int start = 0; start < n - 1; start++) {
    int indexOfMin = start;
    for (int j = start + 1; j < n; j++)
        if (v[j] < v[indexOfMin]) indexOfMin = j;    // 只比较不移动
    swap(v, start, indexOfMin);                       // 每轮恰好一次交换
}
```

- **比较多、搬移少**：比较 1+2+…+(n-1) = n(n+1)/2 次（高斯求和——O(n²) 信号），但每轮只 swap 一次
- **最好=最坏=O(n²)**：扫描结构不因输入而变——已排序的数组照样全扫
- 适用：**移动数据贵**的场景（官方比喻：仓库里挪冰箱——多看少搬）

## 2. 插入排序（insertion sort）："let's gooooo!"（冲冲冲）

把未排序区**第一个元素拖进左边的有序前缀**，遇到更小的就停。

```cpp
for (int start = 1; start < n; start++) {
    int peach = v[start];                  // 🍑 官方命名：拿起"桃子"
    int gap = start;
    while (gap > 0 && v[gap - 1] > peach) {
        v[gap] = v[gap - 1];               // 大元素右移腾位
        gap--;
    }
    v[gap] = peach;                        // 桃子落位
}
```

- **交换多、比较可提前停**：peach 写法比逐对 swap 少一半写次数（一次挪到再落位）
- **最坏 O(n²)**（逆序输入），**最好 O(n)**（已排序：每轮一次比较就停）——"接近有序"的数据上是隐形冠军
- 适用：**比较贵、移动便宜**（官方比喻：跑步排名——比较费脑子，挪人便宜）

## 3. 归并排序（merge sort）：分治登场

```cpp
void mergeSort(std::vector<int>& v, int lo, int hi) {      // 闭区间
    if (lo >= hi) return;                    // 基例：0/1 个元素天然有序
    int mid = lo + (hi - lo) / 2;            // 📍 防溢出写法（第三次出现了）
    mergeSort(v, lo, mid);                   // 排左半
    mergeSort(v, mid + 1, hi);               // 排右半
    mergeTwo(v, lo, mid, hi);                // 归并两个有序段
}
```

**归并 = 双指针**：i 指左半、j 指右半，反复取较小者进辅助数组，一边耗尽后倒灌另一边（指针有效性检查：`i > mid`、`j > hi`），最后拷回原数组。

**复杂度（递归树分析法）**：

```
第0层:        [n]                ← 归并 n 次
第1层:    [n/2] [n/2]            ← 共 n
第2层:  [n/4]×4                  ← 共 n
 ...每层总工作量 O(n)，共 log₂n + 1 层 → O(n log n)
```

**代价**：不是原地（辅助数组 + 递归栈）；小 n（≤100）时递归开销反而**输给**插入排序；代码与调试更复杂。

**快排一句话预告**（官方 aside，CS161 正式讲）：归并是"**易分难合**"（中间一刀切、合并费劲），快排是"**难分易合**"（按枢轴花力气分、分完天然有序）。

## 4. 官方实测表（TIME_OPERATION 数据）

| 算法 | 最坏 | 最好 | n=1,000 | n=10,000 | n=50,000 |
|------|------|------|---------|----------|----------|
| 选择 | O(n²) | O(n²) | 1.04 ms | 99.1 ms | 2434 ms |
| 插入 | O(n²) | **O(n)** | 0.56 ms | 55.0 ms | 1375 ms |
| 归并 | **O(n log n)** | O(n log n) | 0.10 ms | 1.28 ms | **7.4 ms** |

读表三得：① n² 与 n log n 在 5 万时差 **300 倍**；② 小 n 时插入最快（0.56ms < 0.10? 不——n=1000 时归并仍快，但 n≤100 时反转，练习实测）；③ 选择全程垫底但**交换次数最少**——操作类型匹配场景比阶级更重要。

## 5. 常见误区清单

1. 以为已排序输入能让选择排序变快——它的扫描结构不变，最好=最坏
2. mid 写 `(lo+hi)/2`——第三次踩同一个坑（递归、二分、归并三连）
3. 归并的辅助数组忘了拷回 / 归并时只用 `<` 导致**稳定性**丢失（取相等时优先左边——这是稳定性的来源）
4. 忽视小 n 反转：n≤100 时插入排序赢——**真实的 std::sort 是混合算法**，小区间正是切到插入
5. 双指针归并忘检查单边耗尽（`i > mid` / `j > hi` 的守卫）

## 6. 与超算比赛的联系

- **std::sort 是 introsort**（快排+堆排+插入混合，小区间切插入）——"混合策略"来自本讲的实测反转，工业级排序全在用
- 归并是**可并行排序**的骨架：两半天然独立可分给两个核（分治=并行的天然来源，模块 06 的伏笔兑现）；大规模并行排序（样本排序/位图排序）都在它的族谱上
- Graph500 评测要按规则生成并核对边集——排序是基准流程的一部分
- 稳定性（相等元素保序）在赛题的多关键字排序里是隐性需求
