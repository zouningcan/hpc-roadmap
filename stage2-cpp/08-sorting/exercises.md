## B 动手题

**B1（三连实现——官方备考核心）** 从零实现 `selectionSort / insertionSort / mergeSort`（归并含 mergeTwo 辅助函数），并验证正确性：
```cpp
// 测试驱动：
std::vector<int> data;
for (int i = 0; i < 1000; i++) data.push_back(rand() % 10000);
std::vector<int> ref = data;
std::sort(ref.begin(), ref.end());        // 标准答案
selectionSort(data); assert(data == ref); // 三个算法各来一遍
```
（用 std::sort 的输出当"测试预言"——模块 07 C3 的 cross-check 思想。）
*考察点：三个算法的完整实现 + 预言机测试法。*

**B2（复现官方实测表）** 用 chrono 对三个算法分别测 n = 1000、10000、50000 的随机输入耗时，填进你自己的表格，和讲义第 4 节官方数据对量级。n×10 时三者耗时各 ×几？和 O(n²)/O(n log n) 预测一致吗？
*考察点：把官方表亲手长出来。*

**B3（插入排序的高光与谷底）**：
1. **已排序输入**（100 万元素 1..n 顺序）测插入排序耗时——O(n) 的样子？
2. **逆序输入**（n..1）再测——O(n²) 的样子？
3. 同样两组输入测选择排序——基本没变化？为什么？
*考察点：最好/最坏用例的真实形态。*

**B4（🕷 小 n 反转实测）** 在 n = 10, 30, 50, 80, 100, 200, 500 的随机输入上对比插入 vs 归并，找出**交叉点**（谁在多小的 n 上领先）。
*考察点：递归开销在小 n 吃掉阶级优势——工业排序混合策略的依据。*

## C 挑战题

**C1（混合排序——当一回标准库作者）** 给归并排序加"小区间切换"：当 `hi - lo < 阈值` 时改用插入排序，阈值取 B4 测出的交叉点。对比纯归并与混合版在 n=10 万的耗时。**这就是 std::sort 家族的思路**——你的阈值调优报告（不同阈值下的耗时曲线）就是一次微型的工程调参实践。
*考察点：理论（阶级）+工程（常数/开销）的混合决策。*

**C2（自底向上的迭代归并）** 把递归归并改成纯循环版：width 从 1 开始每轮翻倍，两两归并相邻块。递归版 vs 迭代版：结果一致性？耗时差异？迭代版省掉了什么开销？
*考察点：递归↔迭代改写（模块 06 B4 的技能迁移）；消除调用栈的意义。*

**C3（稳定性的实证）** 构造 `struct Player { string name; int score; };` 若干，按 score 排序（同分保输入序）：
1. 手写稳定归并（相等取左）验证同分者保序
2. 手写"选择排序"版验证它**不稳定**（给出一个被换乱顺序的具体反例）
3. `std::stable_sort` 对照
*考察点：稳定性不是性能属性而是**语义属性**——多关键字排序的正确性根基。*
