# 模块 06（stage2）参考答案

## A1

基例（答案直接已知的终止条件）+ 递归步（分解成更小同类子问题）。不朝基例推进 = 每次调用压一帧栈、永不弹出——栈内存（~8MB）耗尽即**栈溢出崩溃**（官方演示约 26 万层）。

## A2

递归调用在语句**前面**时：先一路钻到基例（printStringReverse 钻到空串），**返回的路上**才逐层执行"打印首字符"——最深那帧（字符串最末字符）最先打印，整串倒序输出。栈帧的生命周期：调用时压栈挂起，返回时弹栈继续——"挂起点之后的代码"按弹栈逆序执行。

## A3

string **传值**：每层调用把 soFar 整串拷贝一份，长度从 0 涨到 n，总拷贝成本 O(n)×O(2ⁿ)。改成 `const std::string&`（或累积在固定缓冲里）降到 O(2ⁿ)。（又一次：拷贝税把复杂度抬一个因子——和模块 01 传值 vectorSize 同根。）

## A4

a) lo、hi 均接近 INT_MAX（约 2.1×10⁹）时 lo+hi 溢出 int，回绕成负数——mid 变负，下标访问未定义行为。
b) 恒等变形：`lo + (hi - lo)/2` 先做减法，hi−lo ≤ 数组长度远小于 INT_MAX，永不溢出；代数上 `lo + (hi−lo)/2 = (2lo + hi − lo)/2 = (lo+hi)/2`。∎

## A5

输出**残缺且重复**：第 i 轮迭代用的 s 是上一轮交换后**没还原**的状态，位置 k 之后字符乱序，某些排列丢失、某些重复出现。"改动-递归-撤销"三步齐全 = 每个分支在**干净状态**上开始，互不污染——这正是回溯算法的完整雏形（下一模块正式展开）。

## A6

a) 恒返回 true 的函数在只含回文（真）用例的测试下全绿——**测试集必须含负例**（非回文用例）才有判别力；理想还要有边界（空串、单字符）。
b) `factorial(0)` 直穿 `n==1` 基例，一路递归到负数方向，永不终止 → 爆栈。基例要**覆盖所有合法输入**（0 是合法的阶乘输入）。

## B2

1) 16 行（2⁴）。2) 24 行（4!），soFar+rest 按字符顺序枚举是字典序。3) 删 unswap：行数仍打印但**内容错乱重复**——同一前缀下出现不该有的排列、部分排列永远出不来（状态被前面分支污染）。典型现场：会看到重复行、`grep -c` 数不出 24 个唯一串。

## B3

"muffins" 正序打印 m-u-f-f-i-n-s；反转版 s-n-i-f-f-u-m。
追踪表（"abc"）：
- 正序：进入 f("abc") 打 'a' → f("bc") 打 'b' → f("c") 打 'c' → f("") 返回
- 反转：进入 f("abc") **先递归** → f("bc") 先递归 → f("c") 先递归 → f("") 返回 → 打 'c' → 返回 → 打 'b' → 返回 → 打 'a'

## B4 参考

```cpp
int bs(const std::vector<int>& v, int key, int lo, int hi, int& cmp) {
    if (lo > hi) return -1;
    int mid = lo + (hi - lo) / 2;
    if (++cmp && v[mid] == key) return mid;      // 计数器
    if (v[mid] < key) return bs(v, key, mid + 1, hi, cmp);
    return bs(v, key, lo, mid - 1, cmp);
}
// wrapper：int bs(v, key) { int c=0; int r=bs(v,key,0,(int)v.size()-1,c); ... }
```
100 万元素：命中约 15–20 次比较（log₂10⁶≈19.9）；不存在值走到 `lo>hi` 约 20 次；首/尾元素同样 log 级。迭代版：`while (lo <= hi) { mid=...; if/else if/else 调整 lo/hi; }`。

## B5 参考现象

流式 cout 版比 vector 收集版慢一个数量级上下（终端 I/O 是最贵的"输出设备"）。收集版：`out.push_back(soFar)` 在基例处，最后一次性打印/或仅返回总数。1296 = 6⁴ 验证生成器正确性——**用组合数学当测试预言**（cross-check）是官方演示的方法论。

## C1

## C2 参考

```cpp
int hanoi(int n, char from, char to, char via) {
    if (n == 0) return 0;
    int steps = hanoi(n - 1, from, via, to);        // n-1 块让路
    std::cout << "move disk " << n << ": " << from << " -> " << to << "\n";
    return steps + 1 + hanoi(n - 1, via, to, from); // n-1 块压上来
}
```
n=3 → 7 步；n=10 → 1023 步。复杂度 T(n)=2T(n−1)+1 = **O(2ⁿ)**。64 块 = 2⁶⁴−1 ≈ 1.8×10¹⁹ 步——哪怕每秒挪 10 亿次也要 585 年：传说的"世界末日"是指数增长的宗教表达。

## C3 参考现象

10 字符（362 万排列）与 11 字符（3992 万排列）耗时比约 **9–12×**（≈11×，机器与 I/O 占比会扰动）。阶乘预测：n 从 10 到 11 工作量 ×11——比指数（×2）更陡的曲线。若程序大头是打印，先做 B5 的收集化改造再测，比值更纯。
