# 模块 06（stage2）练习：递归

> 分层：A 概念 / B 动手 / C 挑战。🕷 = 高频易错。
> 追踪题一律**先纸笔画栈帧**，再跑代码对答案——递归的懂 = 能预测。

## A 概念题

**A1** 递归的两要素是什么？"子问题必须朝基例推进"不满足时会怎样（机制层面）？
*考察点：基例+递归步；无限递归压爆调用栈。*

**A2** 🕷 `printStringReverse` 只是把 printString 的两行**换序**，输出就反转了。用"钻下去/吐出来"的语言解释为什么。
*考察点：递归调用先执行完、返回路上才执行后续语句——栈帧生命周期。*

**A3** 🕷 官方指出 coinFlip 是 O(n·2ⁿ) 而非 O(2ⁿ)，原因是什么？怎么改回 O(2ⁿ)？
*考察点：string 传值拷贝 × 每层；改传引用。*

**A4** a) `(lo + hi) / 2` 在什么条件下出错、错成什么样？b) `lo + (hi - lo) / 2` 为什么安全？证明两者代数等价。
*考察点：int 溢出边界 ~21 亿；减法先行的恒等变形。*

**A5** 🕷 permuteSwap 删掉第二个 swap（撤销）会发生什么？为什么"改动-递归-撤销"必须三步齐全？
*考察点：状态污染；回溯的前置理解。*

**A6** a) 为什么只含 true 用例的回文测试骗过恒真函数？正确的测试集必须覆盖什么？b) `factorial` 基例写 `n==1` 的隐患？
*考察点：负例的尊严；0 输入直穿基例爆栈。*

## B 动手题

**B1（栈帧追踪：纸笔+机验）** 画出 `factorial(4)` 的完整栈帧序列（每帧一行：压栈时写"求 4×f(3)"，弹栈时写"返回 24"）。然后给 `isPalindrome("racecar")` 同样画一份（剥首尾的每步子串）。
*考察点：追踪能力——递归考试的基本功。*

**B2（枚举器双打：coinFlip 与 permute）**：
```cpp

// 2) permute("", "abcd")：输出多少行？是不是 4!？字典序吗？
```

*考察点：2ⁿ/n! 的计数直觉；状态污染的现场观察。*

**B3（printString 正反对比实验）**：

**B5（性能二课实测，L10 官方实验）** rollD6 用 soFar 版生成 4 个骰子的全部序列：

## C 挑战题

**C1（中点溢出复现）** 构造 lo、hi 接近 INT_MAX 的场景证明 `(lo+hi)/2` 出错：
```cpp
int lo = 2000000000, hi = 2100000000;
std::cout << (lo + hi) / 2 << " vs " << lo + (hi - lo) / 2 << "\n";
```
输出各是什么？再用 `<climits>` 的 INT_MAX 解释。然后回答：多大的数组会遇到这种 lo/hi？
*考察点：亲眼看到负数中点；20 亿元素级才触发——"低概率≠不用防"。*

**C2（汉诺塔——递归三大名题补全）** 实现 `hanoi(n, from, to, via)` 打印移动步骤并返回步数：
- 分解：n-1 块从 from 挪到 via → 第 n 块 from 挪 to → n-1 块从 via 挪 to
- 验证步数 = 2ⁿ - 1（n=3 时 7 步，n=10 时 1023 步）
- 用模块 05 的语言：这个算法的复杂度是多少？为什么"64 块金片的传说"等于世界末日？
*考察点：三分步分解；2ⁿ-1 的来源；指数的宗教感。*

**C3（permute 的 O(n!) 手感）** soFar 版 permute 分别跑 "abcdefghij"（10!=362 万）和 "abcdefghijk"（11!=3991 万），计时。时间比接近多少？与"n 多 1、工作量 ×11"的阶乘预测吻合吗？（机器慢可降到 8/9 个字符，看比值即可）
*考察点：阶乘增长的体感——比指数更绝望的那条曲线。*
