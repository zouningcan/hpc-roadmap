# 模块 13（stage2）练习：哈希

> 分层：A 概念 / B 动手 / C 挑战。🕷 = 高频易错。

## A 概念题

**A1** 官方开题的三种旧方案（巨型数组/有序数组/BST）各自的死穴？哈希表"两全其美"美在哪？
*考察点：空间 vs 查找 vs 插入的三角；平均 O(1)+O(n) 空间。*

**A2** 好哈希函数的四条军规？首字母哈希违反了哪几条、为什么？
*考察点：确定性/均匀/大值域/相似→相异；首字母版违反后三条（值域 26）。*

**A3** 线性探测的**删除**为什么不能直接清空格子？脏标记（dirty）方案怎么工作？
*考察点：截断探测链；插入可复用、搜索穿透。*

**A4** a) 负 hash code 怎么产生、mod 之后得到什么？b) 为什么 `abs()` 救不了 INT_MIN？
*考察点：溢出→负数；-2147483648 的 abs 溢出是 UB。*

**A5** 负载因子的定义与含义？太大太小各有什么病？扩容时为什么必须**全部重插**？
*考察点：n/b=平均链长；长链/浪费；mod 除数变了下标全变。*

**A6** 哈希表操作的"O(1)"带哪两个隐藏限定？全撞一处时插入 n 个的总代价是多少（用哪个求和公式）？
*考察点：平均+哈希自身O(k)；1+2+…+n=O(n²) 高斯和。*

**A7** std::map 和 std::unordered_map 的内部结构、复杂度、遍历序分别是什么？怎么选？
*考察点：红黑树 O(log n) 有序 vs 哈希平均 O(1) 无序；要有序遍历/范围查询选前者。*

## B 动手题

**B1（手推哈希下标）** 表长 10，哈希函数 `h(k) = (k*7) % 10`：
1. 依次插入 4, 14, 24, 7——用**线性探测**画每步的数组状态
2. 同样四个键用**分离链接**画桶+链表状态
3. 本例的负载因子是多少？链平均多长？
*考察点：两种策略的手感对照——先纸笔后编程。*

**B2（MiniIntSet 两种引擎）** 分别实现：
```cpp
// 引擎一：线性探测（表长 2n、脏标记删除、满表检查）
class LPSet { /* insert / contains / remove */ };
// 引擎二：分离链接（负载因子 > 1.0 时倍扩 rehash）
class SCSet { /* insert / contains / remove */ };
```
随机 10 万元素压测：全部插入后逐一 contains（应全真）+ 移除一半后再查（删的假、留的真）。
*考察点：两种冲突策略的完整落地；删除语义的正确性测试。*

**B3（🕷 负下标现场）** 构造负 hash code 的复现：
```cpp
long big = 2147483647L * 3;                  // 让 int 运算溢出
int  bad = (int)(big % 1000000007);
std::cout << bad % 10 << "\n";               // 可能输出什么？
```
a) 解释负数怎么来；b) 给出两道防御（提示：全程用 `unsigned`/`long long` 做 hash，或先 `%` 后判负加表长）。
*考察点：官方坑的亲手复现与修复。*

**B4（twoSum 三级跳——官方压轴）**：
1. 暴力双循环版（计时基准）
2. 哈希版（`unordered_set` 见过集合）
3. `unordered_map` 进阶版：返回**下标对**而不是值对
10 万元素随机数据上对比 1/2 的耗时；再测"全部落在末尾才有解"的刁钻用例。
*考察点：官方结课题的完整谱系；哈希换 O(n) 的实测。*

## C 挑战题

**C1（坏哈希的代价实测）** 用 `h(s) = s[0] - 'a'`（首字母）和 `std::hash<string>` 分别驱动你 B2 的 SCSet，插入 10 万个**真实英文单词**（/usr/share/dict/words 或造词）：
1. 两种哈希下最长链各多长？（给 SCSet 加个 debug 统计）
2. contains 最坏耗时差多少倍？
*考察点：均匀性失效的量化——26 个桶扛 10 万词的惨案。*

**C2（字符统计的两种引擎对决）** 10MB 文本按词统计词频：`std::map` vs `std::unordered_map` 各计时。差距多少？再测**遍历输出**两者行为差异。结合模块 05 C3（n 的定义：不同词数）解释为什么差距没有理论 O(log n) 那么大。
*考察点：树/哈希的真实工程对比；理论阶与实测常数的辩证。*

**C3（一致性体验：哈希种子与恶意输入）** `std::hash` 对同一路径每次运行结果相同（固定种子）。写一个把 0..N 全部映射到同一下标的"恶意哈希"装进你 B2 的 LPSet（表长 100，全撞 index 0），测插入 1000 个元素的耗时；对照均匀哈希同测。**这就是"最坏 O(n) / O(n²)"的攻击现场**——并解释哈希种子随机化（如 Python 的 PYTHONHASHSEED）防的是什么。
*考察点：算法复杂度攻击（DoS via hash collision）；防御机制的存在理由。*
