# 模块 13（stage2）参考答案

## A1

巨型数组：O(1) 操作但开 1 亿格浪费到爆；有序数组：省空间但插入要挪人+维护有序 O(n) 起，查找 O(log n)；平衡 BST：最坏 O(log n) 但每节点指针开销、常数大（std::map 内部）。哈希表：**平均 O(1) 操作 + O(n) 空间**——兼得前两者的优点。

## A2

确定性、均匀分布、值域大、相似输入→相异输出。首字母哈希：确定性 ✔，但值域封顶 26（违反"值域大"）、真实词汇首字母分布严重不均（s/t/a 扎堆，违反"均匀"）、`item1/item2` 只差末尾却同桶（违反"相似→相异"）——三条全踩。

## A3

探测链依赖"从起点连续找到目标"的路径完整性；把中间格清空，搜索走到空格会判定"没有"——**藏在更后面的同伙被截断失踪**。脏标记：格子弹出一个"删过"状态——插入可把它当空位复用，搜索则**穿透它继续探测**；脏格积累太多时整体 rehash 恢复干净。

## A4

a) 哈希中间量用 int 存放，乘法/加法溢出回绕成负数；负数 mod 正数（C++ 截断除法）得**负下标**——非法索引，越界写内存。
b) `abs(INT_MIN)` = 2147483648 > INT_MAX，本身溢出（UB），还是救不回来。防御要从**计算全程用更宽/无符号类型**入手，而不是事后取绝对值。

## A5

负载因子 = n/b = **平均每条链的长度**（链长就是平均一次查找要走的步数）。太大：链长、操作退化；太小：空桶与指针浪费。扩容后除数（表长）变了，`hash % newB` 的结果与旧表**没有任何对应关系**——只能全部重新哈希重插。

## A6

限定一：O(1) 指**平均**情形（最坏 O(n)）；限定二：默认哈希函数自身 O(1)——串长 k 的键实际 O(k)。全撞一处：插入第 i 个要探测/比较 i 次，总计 1+2+…+n = n(n+1)/2 = **O(n²)**（高斯和——第三次遇到它：选择排序、permute 头插、现在哈希灾难）。

## A7

| | std::map | std::unordered_map |
|---|---|---|
| 内部 | 红黑树（自平衡 BST） | 哈希表（链接法） |
| 查找/插入 | 最坏 O(log n) | 平均 O(1)，最坏 O(n) |
| 遍历序 | **按键升序** | 无序 |
选择：需要有序遍历/范围查询（lower_bound）→ map；只要快速键值存取、量大 → unordered_map（HPC 默认）。

## B1 参考

h(4)=8、h(14)=8、h(24)=8、h(7)=9——三兄弟全撞 8！
1) 线性探测：4→arr[8]；14→撞，探到 arr[9]；24→撞 8、9，回卷到 arr[0]；7→h=9 被占，回卷 arr[1]。数组：`[24, 7, _, ..., _, _, _, _, 4, 14]`
2) 链接：桶8→(4→14→24)，桶9→(7)
3) 负载因子 = 4/10 = 0.4；链平均 0.4（桶 8 独扛 3 人——小样本的"不均匀"预演聚簇问题）。

## B2 参考

LPSet 要点：表长开 2n 上限、三态格子（空/占用/脏）、insert 前查满、contains 穿透脏格、remove 只打脏不真清。SCSet 要点：桶数组 vector<list<int>>（或手搓链）、_size/_buckets 比值超 1.0 时倍扩+rehash。压测三段式（全插全查/删半再查）正是官方"删除语义"的正确性验收。

## B3 参考

a) `(int)` 截断把 long 的溢出结果变成负 int（回绕）；负数 % 正数 → 负余数 → 负下标。
b) 防御一：哈希计算全程 `long long`/`size_t`（无符号回绕是良定义的）；防御二：`idx = ((code % b) + b) % b`（数学把负余数抬回 0..b-1）。

## B4 参考

暴力 O(n²)：10 万元素"末尾才有解"用例要 ~10¹⁰ 次比较（分钟级）；哈希版 O(n)：**毫秒级**——差距随 n 拉大到"跑完 vs 跑不完"。进阶版用 `unordered_map<int,int>`（值→下标），查补数时直接拿它的下标。

## C1 参考现象

首字母版：10 万词挤进 26 个有效桶，最长链**数千**（s/t 开头的桶爆仓）；std::hash：最长链 1~3。contains 最坏耗时差 **百倍级**——均匀性不是玄学，是链长的直除数。

## C2 参考现象

插入统计阶段 unordered 通常快 2~5×（不是理论的 ~17×：去重后独立词数 n' 远小于总词数，log n' 小；且 map 的树节点连续分配缓解缓存劣势）；遍历输出：map **字典序**整齐，unordered 乱序（桶序）。工程结论：量小或要序 → map 无妨；量大纯查找 → unordered。

## C3 参考

恶意哈希（`return 0;`）下 1000 个元素全在 index 0 排队：插入总探测 1+2+…+1000 ≈ 50 万次，毫秒内可见地变慢；规模再大就是**秒级/分钟级**——这就是**哈希碰撞 DoS**：攻击者构造一批全撞的键（如恶意 JSON/POST 参数），把服务端的"O(1)"逼成 O(n²)。哈希种子随机化让攻击者**无法预测下标分布**、构造不出稳定全撞的输入——防的是"复杂度攻击"而非偷数据。
