## 0. 一句话定位

**数组 + 哈希函数 = 平均 O(1) 的字典**。模块 04 说 unordered_map "平均 O(1)"，本模块把这台机器拆开给你看——"平均"两个字里藏着全部工程。

## 1. 动机：三种旧方案 vs 哈希表（官方开题）

存 1.7 万条学生记录、键是 8 位学号，三条老路：

| 方案 | 空间 | 操作 | 死穴 |
|------|------|------|------|
| 巨型直接索引数组（开 1 亿格） | 浪费到爆 | O(1) | 空间 |
| 有序数组 + 二分 | O(n) | 查 O(log n) | 插入要挪人+重排序 |
| 平衡 BST（std::map 的内部） | O(n) + 指针开销 | 最坏 O(log n) | 指针跳转、常数大 |

**哈希表 = 两全其美**：平均 O(1) 操作 + O(n) 空间。官方点题：**花点额外空间能买大把运行时间**（模块 11 双向链表同一条经济学的再现）。

## 2. 核心机制

```
key --哈希函数--> hash code（大整数） --mod 表长--> 数组下标
```

学号 `05123456` 直接当 hash code，`mod 10` 得下标 6——放 arr[6]。

**冲突（collision）不可避免**（抽屉原理：键的宇宙无限大、格子有限），两大解法见下。

## 3. 好哈希函数的四条军规（官方）

1. **确定性**：同输入必同输出（每次算不一样，存进去就找不回了）
2. **均匀分布**：输入均匀时输出摊满所有下标（70% 挤一个格 = 灾难）
3. **值域要大**：大小表都能配合
4. **相似输入 → 相异输出**：真实数据爱扎堆（"张伟"们、"item_"前缀们），函数得把堆打散

🕷 **官方反例**：`myHash(s) = s[0]-'a'+1`（首字母）——26 个取值封顶，n 一大必然血崩；考试还会让你分析"为什么它确定性满分却是坏函数"（违反 2/3/4 条）。

## 4. 冲突策略一：线性探测（linear probing，开放寻址）

撞了就**往后找下一个空格**，到头回卷：`(hashCode + i) % tableSize`。

🕷 **三个官方坑**：

1. **负 hash code**：整数溢出可能产生负数，C++ 里负数 mod 正数得**负下标**（非法）；而 `abs()` 对 `INT_MIN` 本身也是 UB——防御要从根上防溢出
2. **删除难题**：直接清空格子会**截断探测链**（后面的同伙再也找不到了）——解法是打"**脏标记（dirty）**"：插入可复用脏格，搜索照常穿透；脏格太多就 rehash
3. **聚簇（clustering）**：一大团连续占用让探测变 O(n)。官方处方：表长开到 2n（空间仍是 O(n)），**装载 25%–50% 为宜**——"呼吸感"是开放寻址的生命线

## 5. 冲突策略二：分离链接（separate chaining）

数组每格是一条**链表**；撞车的挂同一条链，插入 O(1) 挂头（顺带红利：最近插入的最先被摸到，可按访问频率调整挂序）。

**负载因子（load factor）= n / b**（元素数 ÷ 桶数）= **平均链长**。官方演示 8/10=0.8：平均每链不到一人。太高 → 链变长；太低 → 空格与指针浪费。工程惯例 1.0 上下触发**扩容**。

**扩容 = 全体重插（rehash）**：mod 的除数变了，**每个元素的新下标都要重算**——单次昂贵，倍增策略摊还后插入仍 O(1)（模块 05 摊还分析的又一实例）。

## 6. 复杂度与两个"但是"

| 操作 | 最好 | 平均 | 最坏 |
|------|------|------|------|
| 插入/查找（两种策略同） | O(1) | **O(1)** | **O(n)** |

- **但是一**："O(1)" 默认指**平均**（官方原话：不带限定的 O(1) 是惯例上的平均情形）；**全撞一处时**插入 n 个的总代价是 1+2+…+n = O(n²)（高斯和，模块 05 的信号再现）
- **但是二**：O(1) 假设**哈希本身 O(1)**——长度 k 的字符串哈希要扫全串，操作实为 O(k)

## 7. HashSet / HashMap

哈希表背书的容器（对照 std::unordered_set/map）：平均 O(1) 操作，**遍历序不保证有序**（std::map 才有序）——模块 04 的"有序 vs 无序怎么选"至此有了机制层的完整答案。

## 8. 压轴：twoSum（官方结课题）

在 vector 里找和为 target 的两个数。暴力双循环 O(n²)；哈希一扫 O(n)：

```cpp
std::pair<int,int> twoSum(const std::vector<int>& v, int target) {
    std::unordered_set<int> seen;                 // 我见过的数
    for (int x : v) {
        if (seen.count(target - x)) return {target - x, x};   // 补数来过！
        seen.insert(x);
    }
    return {-1, -1};
}
```

套路名：**"用哈希把'找过没'从 O(n) 降到 O(1)"**——见过集合 + 边走边查补数。这一招在比赛与面试中出现频率极高。

## 9. 常见误区清单

1. 认为 O(1) 无条件成立——是**平均**，且哈希本身要 O(k)
2. 线性探测的删除直接清格——截断探测链，必须脏标记
3. 忘防负 hash code（溢出 → 负 mod → 负下标）
4. 装载因子不管不扩容——聚簇/长链把 O(1) 磨成 O(n)
5. 首字母类哈希当"够用"——值域 26 的天花板
6. 期望 unordered 遍历有序——它从不承诺

## 10. 与超算比赛的联系

- **Graph500 的 visited 标记/邻居查重**：大规模图处理里哈希集合是主力（位图+哈希混合是极致优化方向）
- **去重流水线**（HelloHPC 第 6 题魔咒筛选器）：SHA1 校验 + 分类 + 去重的性能支柱就是哈希
- **哈希种子随机化**：防"恶意构造全撞"的输入（模块 05 C2 提过最坏 O(n²)）——线上服务与评测机的共同防御
- 均匀性 vs 局部性的取舍：完美哈希/布隆过滤器是 HPC 与大数据的进阶武器（本模块的地基）
