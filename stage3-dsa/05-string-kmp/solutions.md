# 模块 05（stage3）参考答案

## A1

触发：文本与模式大量共享前缀且总在最后一格失配——T=`AAAA…A`、P=`AAAB`。每个对齐位比对 m-1 次后失败、i 回退重来。根源：**每次失配把已比过的字符信息全部丢弃**（i 回退、j 归零）。

## A2

```
"ababab":  j     0  1  2  3  4  5  6
           next -1  0  0  1  2  3  4
"aaaaab":  next -1  0  1  2  3  4  0
"abcabcac":next -1  0  0  0  1  2  3  1
```
next[0]=-1：表示"模式滑出比较区"，主循环据此右移 T 指针——若写 0，首字符失配时 j 永远在 0 打转，死循环。

## A3

失配发生时，P[0..j) 已与 T[i-j..i) 逐字符相等（刚验证过）——这段"已匹配前缀"里，长度为 next[j] 的前缀与紧邻 i 之前的后缀相等，所以把 P 滑到让该前缀对齐那个后缀处，前面的字符**无需再看**——i 不动、j=next[j] 继续。信息没有丢，所以指针不必退。

## A4

`t = next[t]`：构造到位置 j 时失配（P[j]≠P[t]），退而求其次——次长的相等前后缀的长度正是 next[t]（next 的定义套娃）。复杂度：`++j` 每次使 j-t 关系推进、`t=next[t]` 每次使 t 严格减小——**t 的总减小量 ≤ t 的总增加量 ≤ m**，两操作合计 ≤ 2m → O(m)。

## A5

针对：`P[next[j]] == P[j]` 时，滑到 next[j] 后首比较必然再次失配（同一个字符）。改进：透传 `next[j] = next[next[j]]`（跳到第一个不同字符）。复杂度仍 O(n+m)——省的是常数（重复字符越多省得越多）。

## A6

设势 Φ = i + j。匹配成功分支：i、j 各 +1，Φ 增 2；失配分支：i 不变、j 变为 next[j] < j，Φ 严格减。整个过程 Φ 从 0 起、不超过 n+m，且每步非增即减——**失配（减少）次数 ≤ 匹配（增加）次数 ≤ 2(n+m)/2**，总步数线性 → O(n+m)。

## B1 参考

实现见讲义第 3 节（buildNext 与 matchKMP 骨架可直接誊用）；注意 `while (j < m - 1)` 的边界（next 数组长 m）。随机交叉验证：`T.find(P)` 与 matchKMP 返回值应全等——**预言机测试一次抓尽实现毛刺**。

## B2 参考（关键几步）

| 步 | i | j | 动作 |
|----|---|---|------|
| 1-4 | 0→3 | 0→3 | 匹配 abab |
| 5 | 4 | 4→next[4]=2 | 失配(T[4]='a' vs P[4]？实际 T=abababab P=abab：i=4,j=4 越界即命中 0) |

本题在 i=4、j=4 时 j==m 命中返回 0——共 4 步；BF 同样 4 步（首位置直接全中）。换 P="abababab" 的刁钻用例才能拉开差距——设计对比用例本身是练习的一部分。

## B3 参考现象

1. 随机串：BF 与 KMP 几乎同速（随机串上 BF 平均接近线性——失配通常 1~2 步内发生）
2. T=a×10⁶、P=a×999+b：BF **秒级~分钟级**（每个对齐位比 999 次），KMP 毫秒级——差两个数量级以上
3. 大量前缀命中：KMP 仍线性，BF 显著退化
结论：**KMP 买的是"最坏保险"**——平均没赚多少，但把 O(n·m) 的尾巴剪掉了（工程选型：偶发大输入的保险费）。

## C1 参考

两定义等价：next[j] 是"滑动后能安全继续的最大对齐"，对齐成立 ⟺ P 的长 t 前缀 == 已匹配段（P[j-t..j)）的后缀。暴力版：对每个 j 从 t=j-1 往下试、逐字符比对——O(m³)；与线性版对 100 个随机模式逐位断言相等——**定义即规范，暴力即预言机**。

## C2 参考

```cpp
int cycleLen(const std::string& P) {
    // 先算 next（长 m+1 版本）
    int c = (int)P.size() - next[m];
    return (m % c == 0) ? c : m;      // 整除则有循环节 c，否则循环节是自身
}
```
原理：m - next[m] 恰是最短循环节长（next[m] 是"去掉一个循环节后剩的最长相等前后缀"）。"ababab"→2 ✓、"abcabcabc"→3 ✓、"abcd"→4 ✓。此结论是 next 表应用的第一考题（字符串循环节/最小表示家族）。

## C3 参考

逐模式 KMP：总代价 O(k·n + Σm)——k 个模式各自扫全文本，k 大时不可接受（100 模式×10⁶ 文本=10⁸ 起步）。AC 自动机：把全部模式建成 **trie**，每个 trie 节点挂一个**失效指针**——指向"当前节点对应串的最长相等后缀所在的另一个节点"，**本质就是把 next 表从'单串前后缀'推广到'trie 路径的后缀'**。文本只扫一遍，失配沿失效指针跳，总代价 O(n + Σm + 命中数)。grep -F 多模式、入侵检测、敏感词过滤的真实引擎。
