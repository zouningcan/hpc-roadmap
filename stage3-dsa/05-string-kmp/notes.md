## 0. 一句话定位

模式匹配：在文本 T（长 n）里找模式 P（长 m）出现的位置。蛮力 O(n·m)，**KMP 摊还 O(n+m)**——核心武器是**失效函数 next 表**："失配时模式串该滑多远才不漏解"。

## 1. 蛮力匹配（Brute-Force, BF）

```cpp
int matchBF(const char* T, const char* P) {        // 返回首个匹配位（无则 -1）
    int n = strlen(T), m = strlen(P);
    for (int i = 0; i + m <= n; i++) {             // 对齐位
        int j = 0;
        while (j < m && T[i + j] == P[j]) j++;
        if (j == m) return i;
    }
    return -1;
}
```

- 最好 O(n)（首位置命中）；最坏 **O(n·m)**——如 T=`AAAA...A`、P=`AAAB`：每个对齐位都比对到最后一格才失败
- 浪费在哪：**每次失配后 i 回退、j 归零**——已经看过的字符又当没看见

## 2. KMP 的洞察：已看过的信息不浪费

失配时，**前面已匹配的 j 个字符是双方共知的**——它们同时是 T 的子串和 P 的前缀。于是问题变成：

> P 的前 j 个字符里，**最长的"相等前后缀"**是多长？——设为 t，则 P 可直接右滑 `j - t` 格、从 P[t] 继续比对，**i 永不回退**。

```
T:  ...  a  b  a  b  a  ...
P:       a  b  a  b  c
                ↑ 失配于 P[4]='c'
P[0..3]="abab" 的最长相等前后缀 = "ab"（长 2）
→ P 右滑 2 格，从 P[2]='a' 继续，T 指针不动！
```

## 3. next 表（失效函数）

定义：`next[j]` = P[0..j) 的**最长相等前后缀**的长度（前后缀严格短于自身）。

```
P:      a  b  a  b  a
j:      0  1  2  3  4  5
next:  -1  0  0  1  2  3
```

`next[0] = -1`（哨兵：连 P[0] 都失配时，整个模式右移一格、T 前进）。

### KMP 主算法

```cpp
int matchKMP(const char* T, const char* P, const int next[]) {
    int n = strlen(T), m = strlen(P);
    int i = 0, j = 0;                       // i 文本指针（只进不退）、j 模式指针
    while (i < n && j < m) {
        if (j < 0 || T[i] == P[j]) { i++; j++; }     // 匹配则并进
        else j = next[j];                            // 失配：模式滑、文本不动
    }
    return j == m ? i - j : -1;
}
```

### next 表的构造：模式串自己匹配自己

```cpp
void buildNext(const char* P, int next[]) {
    int m = strlen(P), j = 0;
    int t = next[0] = -1;                    // t = 当前最长相等前后缀长
    while (j < m - 1) {
        if (t < 0 || P[j] == P[t])           // 可以延长前后缀
            next[++j] = ++t;
        else
            t = next[t];                     // 失配也用 next 递归回退！
    }
}
```

精妙处：**构造 next 的过程本身就是一次 KMP**（P 匹配 P）——递推式 `next[j+1] ≤ next[j]+1`，且失配时套用已算好的前段。

## 4. 改进的 next 表（nextval）

标准 next 的一处浪费：若 `P[next[j]] == P[j]`，滑过去**必然再失配同样的字符**——改进版在这一步**继续跳**：`next[j] = next[next[j]]`（透传到第一个不同字符）。实测再省约一成比较。

## 5. 复杂度：摊还的正确姿势

邓课的招牌论证（不画摊还树）：匹配循环中 **i 每轮 +1 或 j+1，i+j 单调不减；j 每次 `= next[j]` 至少减 1**——总增量 ≤ n+m，故总递减 ≤ 总增量 ≤ **2(n+m)** → O(n+m)。

几何级数/单调势能——模块 01 工具箱的又一次应用：**"只进不退的量"与"回退次数"配平**。

## 6. 常见误区清单

1. 前后缀允许等于自身——next 定义要求**严格短于**
2. next[0] 写 0——应为 **-1**（否则首字符失配死循环）
3. 主循环里 `i` 回退——KMP 的 i **永不回退**，回退即写错
4. buildNext 的 `t = next[t]` 写成 `t = 0`——递归回退才是线性构造的关键
5. 拿 next 当"滑几格"——next 是"滑到后从哪继续比"，差一个换算
6. nextval 当必胜——它省常数不省阶级，且要求字符集重复较多才明显

## 7. 与超算比赛的联系

- 模式匹配出现在**日志扫描、基因序列（HelloHPC 出过基因组装赛题）、文本预处理**各处——rg/grep 的核心引擎是多模式版的 KMP 家族（AC 自动机）
- **"已见信息结构化保存"**的思想 = 失效函数 = DP 的失败指针版——赛题里"把暴力记忆化"通用套路
- 单调势能论证法 = **摊还分析的手算版**：HPC 通信库的批量发送缓冲、STL 扩容（模块 02）都靠它证明"偶发的贵"不破阶级
- 生物信息赛题（序列比对）是 KMP→DP（edit distance）的直线升级
