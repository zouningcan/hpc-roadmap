> 课程页：https://www.xuetangx.com/course/THU08091002048 （页面抓取限制见阶段 README）
> 前置：模块 06（AVL 与 3+4 重构）。三个主角各治一种病：**Splay 治"访问不均"、B 树治"外存 IO"、红黑树治"删除太贵"**。

## 0. 一句话定位

AVL 之外的三条进化路线：**伸展树**（不存平衡信息、靠"访问即提升"的摊还）、**B 树**（为磁盘页量身定制的矮胖多路树）、**红黑树**（工程界平衡树的默认选择，std::map 的真身）。

## 1. 伸展树（Splay Tree）：访问即提升

**核心操作 splay(x)**：把刚访问过的节点 x **双层旋转搬到根**。之后一切查找/插入/删除都以 splay 收尾。

### 单层 vs 双层伸展（本章灵魂）

- **单层**：每步只和父亲转——最坏情况（链状树交替访问两端）**退化 O(n) 每次**
- **双层（邓课采用）**：先看**祖父**——zig-zig（同侧：先转祖父再转父亲）与 zig-zag（异侧：两次 3+4 重构）——**折半式上搬**
- 结论：双层伸展下**每次操作摊还 O(log n)**（势能法证明），且**路径长度折半**——"越用越顺"

### 为什么敢不存平衡信息

- 优点：节点不存 height、代码远比 AVL 简单、**局部性强**（热数据自动浮到浅层——80/20 分布的真实负载下接近 O(1)）
- 代价：**单次操作无保证**（最坏 O(n)，靠摊还兜底）——实时系统不敢用
- 命运共同体：**访问模式即性能**——与 CPU 缓存、TLB 的"局部性红利"是同一个物理规律

## 2. B 树：为外存而生的矮胖子

**动机换算**：磁盘/SSD 按**页（块）**读写（~4KB），一次 IO 读整页——**树高 = IO 次数**。二叉树存 10 亿键高 30 → 30 次 IO；B 树每节点装几百键（**m 阶**，内部节点孩子数 ∈ [⌈m/2⌉, m]），高仅 3~4 → **IO 次数量级下降**。

```
2-4 树（4阶B树）示例：每个节点最多 3 键 4 孩子
        [ 30 | 60 ]
       /    |    \
   [10|20] [40|50] [70|80|90]
```

### 动态维护两手

- **插入上溢（overflow）**：节点键数超 m−1 → **中间键上提**，节点一分为二——可能向上连锁分裂，根分裂则**树高 +1**（B 树向上长）
- **删除下溢（underflow）**：键数低于 ⌈m/2⌉−1 → 先**旋转**（向富兄弟借），借不到则**与兄弟合并**（连带中位键下拉）——可能连锁合并

### B+ 树一瞥

B+ 树（数据库索引真身）：内部节点**只存路标**、全部数据在**叶子层**且叶子间串成有序链表——**范围查询**（`WHERE id BETWEEN …`）沿链扫即可。

## 3. 红黑树：工程界的默认答案

五条性质（等价视角）：节点红或黑；根黑；**红节点孩子必黑**（无连续红）；**任一节点到叶的黑高度相同**；叶哨兵黑。推论：**最长路径 ≤ 2×最短路径**——高度 ≤ 2·log₂(n+1)。

- 修复用**变色 + 旋转**：插入至多 2 次旋转；**删除至多 3 次旋转**（对照 AVL 的 O(log n) 连锁）——这是工程选它的直接理由
- 与 **2-3-4 树等价**（红节点上折到黑父亲=4节点）——理解红黑树的最好姿势
- 现役：std::map/set、Linux CFS 调度器、epoll、Java TreeMap、nginx 定时器

### 三树对比表

| | AVL | Splay | 红黑树 | B 树 |
|---|------|-------|--------|------|
| 单次保证 | O(log n) 严格 | ❌ 摊还 | O(log n)（松 2×） | O(log_m n) IO |
| 节点额外信息 | height | 无 | 1 bit 颜色 | 键数组 |
| 删除代价 | 连锁旋转 | 摊还 | ≤3 旋转 | 合并/借 |
| 主场 | 查询为主只读 | 局部性负载 | 通用工程 | 外存/索引 |

## 4. 常见误区清单

1. Splay 当实时结构用——单次最坏 O(n)，摊还不救死线
2. 双层伸展写成单层——zig-zig 忘"先祖父后父亲"的顺序（顺序反了就是单层）
3. B 树节点孩子数下界写成 1——非根节点须 ≥ ⌈m/2⌉
4. B 树插入分裂"从叶向上"忘了连锁；删除忘"先借后并"的顺序
5. 红黑树背性质不会用——**2-3-4 等价视角**才是理解与实现的正道
6. 拿 B 树和红黑树比内存性能——B 树的主场是**外存**，内存里节点键数组反而费缓存

## 5. 与超算比赛的联系

- **局部性即性能**（Splay 的哲学）：HPC 的缓存、NUMA、预取全在奖励局部性——赛题数据访问模式分析与此同源
- **块设备换算思维**（B 树的哲学）："一次 IO 读一页"与"一次内存访问带一行缓存"是**同构的批量经济学**——分块矩阵乘的块大小选择、CUDA 的 coalesced 访存，全是这道题的变体
- 数据库/文件系统是 HPC 存储栈的地基（Lustre/GPFS 的元数据索引即 B 树家族）
- 红黑树与 Linux 内核：读调度器/定时器源码（性能优化的必经之路）绕不开它
