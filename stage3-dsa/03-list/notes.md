## 0. 一句话定位

列表 = **双向链表 + 头尾哨兵**：任何位置的插入/删除 O(1)，代价是按秩访问 O(n)。向量与列表是"**循秩** vs **循位置**"的两种世界观。

## 1. 从向量到列表：两种世界观

| | 向量 Vector | 列表 List |
|---|---|---|
| 逻辑/物理序 | 统一（r 号在 r 单元） | 脱钩（节点散落靠指针链） |
| 循秩访问 `L[r]` | O(1) | O(r) |
| 插入/删除（给定位置） | O(n)（搬人） | **O(1)**（改 2~4 个指针） |
| 空间 | 紧凑、缓存友好 | 每节点 pred/succ 双指针开销、缓存敌对 |

## 2. 节点与哨兵：邓课的结构设计

```cpp
template <typename T> struct ListNode {
    T data;
    ListNode<T>* pred;     // 前驱
    ListNode<T>* succ;     // 后继
    ListNode() {}          // header/trailer 用（无数据）
    ListNode(T e, ListNode* p = nullptr, ListNode* s = nullptr)
        : data(e), pred(p), succ(s) {}
};

template <typename T> class List {
private:
    int _size;
    ListNode<T>* header;   // 头哨兵：有 pred 无 succ 语义，不放数据
    ListNode<T>* trailer;  // 尾哨兵：对称
    void init();           // 两个哨兵互相手拉手，_size = 0
};
```

**哨兵（sentinel）的三大红利**：

1. **真实节点永不为首/末**——插入删除不再有"头/尾特例"，一套代码走天下（stage2 模块 11 的"空表/单节点边界矩阵"被结构性消灭）
2. `header->succ` 永远是首元素，`trailer->pred` 永远是末元素——边界访问统一
3. 空表也有合法结构（header↔trailer）——**不变量更简单 = bug 更少**

## 3. 接口：秩接口 vs 位置接口

```cpp
// 位置接口（主力，O(1)）
ListNode<T>* insertA(ListNode<T>* p, T e);   // 紧随 p 之后插入
ListNode<T>* insertB(ListNode<T>* p, T e);   // 紧贴 p 之前插入
T remove(ListNode<T>* p);                    // 删除 p，返回其数据
ListNode<T>* find(T e, int n, ListNode<T>* p) const;   // 自 p 向前 n 个里找

// 秩接口（便捷层，O(r)——内部先走过去）
T& operator[](int r);                        // 从 header 或 trailer 近端走
```

**设计课**：秩接口是糖衣（内部仍是 O(r) 走链），**高频操作必须用位置接口**——API 的复杂度分层要写在脸上。

## 4. 核心操作

**查找 `find`**：从 p 向**前**逐个比对 n 个——O(n)。为什么向前？与"保序插入"配合：新元素插入在查找起点的**紧前方**时，语义与向量版一致。

**去重**：

- `deduplicate()`（无序）：对每个节点在前缀中查重、删后出现的——O(n²)
- `uniquify()`（有序）：相邻必重复，一趟**删除法** O(n)（对照向量版双指针"搬留法"——**搬移 vs 删除**，各有 O(n)，手段随结构而变）

**逆置 `reverse()`**：列表版把每个节点的 pred/succ **对调**（或逐个头插）——O(n)；向量版是双指针对撞交换。

## 5. 列表排序三连（本章重头戏）

### 插入排序（insertion sort）

每个元素向前找**不大于它的最后一个**位置，**接驳**进去。查找 O(n) + 接驳 O(1)，总 O(n²)。注意**从后往前找**可以边扫边比较，且相等时停（**稳定性**由"不大于"保证——等于时不动）。

### 选择排序（selection sort）

每轮扫未排序段找 max，与未排序段末交换。扫描 O(n)×n 轮 = O(n²)。列表版可交换**数据域**（节点不接驳）——简单但节点"身份"漂移。

### 归并排序（merge sort）——列表的主场

```cpp
// 分：快慢指针找中点（不支持下标！）
// 合：merge 不是拷数据，而是【接驳（splice）】——把节点整段摘下来挂过去
```

**分**：快指针走两步慢指针走一步找到中点 O(n)；**合**：双指针比较 + `insertB/remove` 接驳——**数据零搬移**，只有指针操作。总 O(n log n)。

🕷 **向量归并 vs 列表归并的镜像**：向量版"分"是免费的（下标折半）"合"是贵的（搬数据）；列表版"分"变贵了（走链找中点）"合"免费了（接驳）——**结构的成本从合并转移到切分**，总量仍 O(n log n)。

## 6. 常见误区清单

1. 手写插入忘写全四个指针（新.pred、新.succ、前节点.succ、后节点.pred）
2. 哨兵也当数据节点遍历/删除——`p != trailer` 的循环条件
3. 秩接口在循环里用 `L[i]`——每次 O(i)，嵌套后 O(n²) 伪装成 O(n)
4. 列表归并把数据往辅助数组搬——白扔了"接驳零搬移"的结构红利
5. 析构只 delete header/trailer——中间节点全漏（先 clear() 逐个删）

## 7. 与超算比赛的联系

- **哨兵思想是 HPC 边界处理的金标准**：网格计算加**鬼边（ghost cell）**、循环数组加冗余槽——"用空间换特例消除"，比赛代码的边界 bug 少一半
- 列表归并的**接驳（splice）**：不搬数据只改链接——大对象/大数据块的移动哲学（**移动指针而非移动数据**，分布式系统里元数据与数据的分离同源）
- 循秩 vs 循位置的 API 分层 = 性敏感接口设计的基本功
- 缓存敌对性（stage2 C1 实测）依旧成立：HPC 热路径仍以数组为主，列表活在**元数据层**（任务队列、空闲块链）
