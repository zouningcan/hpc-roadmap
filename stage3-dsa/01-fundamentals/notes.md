## 0. 一句话定位

一切数据结构课的"第一性原理"：**什么是计算、怎么度量算法好坏、两大递归策略（减而治之/分而治之）与动态规划**。邓课的招牌是把这三件事讲到"知其所以然"。

## 1. 计算与算法（algorithm）

**算法 = 在有限步骤内解决特定问题的明确指令序列**，五大特性：

1. **输入/输出**（零或多个输入、至少一个输出）
2. **确定性**（每一步含义明确无歧义）
3. **可行性**（每步都能在有限时间内完成）
4. **有穷性**（有限步后终止—— halt 问题告诉我们"自动验证有穷性"不可能，只能靠人证明）
5. （课程强调）**正确性**：对**一切**合法输入给出正确输出，不是"我测过的那些"

**数据结构**：数据在计算机中的**组织、存放与操作方式**——算法处理的对象。邓课引 Dijkstra 语录立意："计算机科学不该叫 knife science，该叫 computing science"——**刀（机器）不重要，切（计算）才是本体**。

## 2. 计算模型：在"理想平台"上度量

比较算法快慢必须先统一"机器"。两个理论模型：

- **图灵机（Turing Machine, TM）**：纸带+读写头，理论计算能力的基石
- **RAM（Random Access Machine）**：寄存器机，任一寄存器 O(1) 访问——**更贴近真实计算机，是复杂度分析的默认平台**

约定：RAM 上执行的基本操作（算术/访存/比较/转移）各计一次——"次数"代替"秒数"（与 CS106B 模块 05"掐表无用论"同源，但这里给出形式化平台）。

## 3. 大 O 记号：渐进复杂度

**O(f)**：当 n 足够大，T(n) ≤ c·f(n)——**上界**；同族还有 **Ω**（下界）、**Θ**（确界）。课程与工程默认谈 **O（最坏上界）**。

记号纪律（与 stage2 一致，此处更正式）：

- 丢常数系数、丢低阶项：`3n² + 200n + 5 → O(n²)`
- **对数记号**：log n 不标底（差常数因子）；来源几乎总是"每次砍半"
- 阶梯：O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)

**邓课特色：级数工具箱**（后面全课程反复用）：

| 级数 | 求和 | 出现场景 |
|------|------|----------|
| 算术级数 Σ1..n | Θ(n²) | 选择排序、插入最坏 |
| 几何级数 1+2+4+…+n | Θ(n) | **倍增扩容摊还**（模块 05/09 的理论根基） |
| 调和级数 Σ1/i | **Θ(log n)** | 装载因子哈希平均查找、快排期望 |
| Σlog i | Θ(n log n) | 建堆的插入版（heapify 是 Θ(n)！） |

## 4. 空间复杂度与"原地"

除输入本身外占用的额外空间：O(1) 称**原地（in-place）**。时间与空间常可互换（模块 11 双向链表 +8 字节换 O(1) 尾删是第一次相遇）。

## 5. 迭代与递归：两大治之策略

### 减而治之（decrease-and-conquer）

**每次削去一个（或常数个）规模单位**，问题规模线性下降：

```cpp
// 线性递归版数组求和：削去一个元素
int sum(int A[], int n) { return n < 1 ? 0 : sum(A, n - 1) + A[n - 1]; }
```

递归深度 O(n)（每层削 1）——**栈的线性开销**是它的代价（模块 06/11 已见识过深递归爆栈）。

### 分而治之（divide-and-conquer）

**切成（通常对半的）子问题，分别求解后合并**：

```cpp
// 二分递归版数组求和：对半分
int sum2(int A[], int lo, int hi) {          // [lo, hi)
    if (hi - lo <= 1) return A[lo];
    int mi = (lo + hi) >> 1;
    return sum2(A, lo, mi) + sum2(A, mi, hi);
}
```

同一问题两种解：总工作量都是 O(n)，但**递归深度从 O(n) 降到 O(log n)**——分治的形状是**平衡二叉树**（模块 12 的直觉前置）。通用方程 T(n) = 2T(n/2) + O(1) → O(n)。

## 6. 动态规划（dynamic programming）初见：Fibonacci 三部曲

**朴素递归**：`fib(n) = fib(n-1) + fib(n-2)`——O(2ⁿ)，因为**同一子问题被反复求解**（递归树里 fib(n-2) 出现两次、fib(n-3) 三次……按黄金比例爆炸）。

**记忆化（memoization）**：算过的存表、先查表再递归——O(n) 时间 O(n) 空间。"**不重复计算**"是 DP 的第一原则。

**迭代 + 滚动变量**：自底向上，只留最近两个值：

```cpp
int fib(int n) {
    int64_t g = 0, f = 1;                 // fib(0), fib(1)
    while (n-- > 0) { g = g + f; f = g - f; }   // 滚动前移
    return g;
}
```

O(n) 时间 **O(1) 空间**——DP 的终极形态之一。三部曲是"**重叠子问题 → 记忆化 → 自底向上压状态**"的标准演化路线（stage2 模块 07 C2 的背包缓存是同一思想的第二次相遇）。

**递归的消除**：尾递归（返回值就是递归调用的返回值，如线性递归求和）总可机械改写为循环——编译器常做尾调用优化，但 C++ 不保证，**安全起见手写迭代**。

## 7. 常见误区清单

1. 大 O 是"上界"不是"恰好"——Θ 才是紧的；平时说 O 其实都想要 Θ
2. log n 不写底——底数差的是常数因子，不是阶级
3. 调和级数求和当 O(n)——是 **Θ(log n)**，哈希与快排期望的命根
4. 分治=快：分治只改**递归树形状**（深度 log n），总工作量取决于每层合并代价——归并每层 O(n) 故 O(n log n)，求和每层 O(n) 一样是 O(n)
5. 朴素 fib 慢是因为"递归"——不，是因为**重复子问题**；记忆化递归照样 O(n)
6. 尾递归一定被优化——C++ 不保证，别赌编译器

## 8. 与超算比赛的联系

- **级数工具箱是 HPC 分析的家常饭**：扩容策略（几何级数摊还）、快排期望（调和级数）、建堆（Σlog i vs heapify Θ(n)）
- 减治/分治 = 模块 06 说的"并行的天然来源"：分治树天然映射到任务并行（stage4 OpenMP task 的理论形状）
- **DP 的记忆化思想在赛题优化里反复出现**：HelloHPC 第 5 题的 sin/cos 预计算表 = "不重复计算三角函数"
- RAM 模型的"每次访存 O(1)"假设在缓存面前**就是错的**——HPC 的全部文章（模块 02 行优先实验）都写在这个假设的破绽上
