# 模块 01（stage3）参考答案

## A1

输入输出（≥1 个输出）、确定性、可行性、有穷性、正确性。正确性要求对**一切合法输入**成立——有限测试只能证伪不能证明（Dijkstra：测试只能证明 bug 存在，不能证明 bug 不存在）。

## A2

O = 上界（不超过 c·f）、Ω = 下界、Θ = 紧界（上下都卡住）。平时说"O(n log n)"其实想要 **Θ(n log n)**（恰好这个阶级）——工程口语把两者混用，理论场合要分清。

## A3

| 级数 | 和 | 场景 |
|------|-----|------|
| 1+2+…+n | Θ(n²) | 选择排序比较数、头插 vector |
| 1+2+4+…+n | Θ(n) | 倍增扩容总搬移（摊还 O(1) 的来源） |
| 1+1/2+…+1/n | Θ(log n) | 链地址哈希平均链查找、快排期望 |
| Σlog i | Θ(n log n) | 逐个插入建堆（对照 heapify 的 Θ(n)） |

## A4

a) 减治：每步削去**一个（常数个）**单位，递归树是一条**链**（深度 n）；分治：切成**对等的两半**，递归树是**平衡二叉树**（深度 log n）。
b) 总工作量都是 O(n)，差别在**递归深度（栈开销与爆栈风险）**：线性版 O(n) 帧、二分版 O(log n) ≈ 20 帧。

## A5

真正原因：**重叠子问题**——fib(n-2) 被算 2 次、fib(n-3) 3 次……子问题按黄金分割比例重复，总量指数爆炸（调用数 ≈ 2·fib(n)）。记忆化：每个子问题只真正求解一次，其余查表 O(1)——n 个子问题 × O(1) = O(n)。

## A6

尾递归：递归调用是函数的**最后一个动作**（返回值直接透传）。C++ 标准不要求尾调用优化（TCO），编译器可做可不做——栈深度没有保证；**生产代码手写循环版本**才安全。

## B1 参考

迭代深度 0；线性递归深度 = n = 10⁶；二分递归深度 ≈ ⌈log₂10⁶⌉ = 20。10⁶ 深度是否爆栈取决于每帧大小（本例每帧 ~32-48 字节，10⁶ 帧约 32-48MB > 8MB 默认栈——**会爆**！可 `ulimit -s` 加大或说明原理）；二分版永远安全。结论：**同为 O(n)，深度差 5 万倍**——这就是分治的第二重红利。

## B2 参考

1. fibRec(35)：calls ≈ 2×fib(35)-1 ≈ **2.9×10⁷**（调用数与 fib 值线性相关——黄金分割树）
2. fibMemo(90)：每个 n 只算一次，calls ≈ 90；fibIter(90)：0（无递归）
3. fibRec(50)：calls ≈ 2×fib(50) ≈ 4×10¹⁰——按每秒 10⁸ 次调用约 **400 秒**起步，实际更慢；fib(90) = 2880067194370816120（>int 范围，必须 long long；fib(93) 逼近 int64 上限）。

## B3 参考

h(10³)≈7.485、h(10⁶)≈14.393、h(10⁹)≈21.301——ln(10³)≈6.9、ln(10⁶)≈13.8、ln(10⁹)≈20.7，加欧拉常数 γ≈0.577 吻合。n 乘 10⁹ 倍（1→10 亿），h 只从 1 涨到 21.3——**对数增长：几乎不涨**。这就是"哈希平均链长 Θ(log n) 很短"和"10 亿元素二分 30 步"的数学本体。

## B4

排序（高→低）：**2ⁿ/1000 ≫ n³/100 > 100·n² > n·log n > √n > log³n > 调和级数(log n) > 几何级数求和(n)**——注意两个陷阱：几何级数求和是 Θ(n)（不是 log n）；log³n 虽是三次方仍低于 n^ε（任意 ε>0）。

## C1 参考

```cpp
long long qpow(long long x, long long n, long long m) {
    long long r = 1; x %= m;
    while (n > 0) {
        if (n & 1) r = r * x % m;
        x = x * x % m;            // 平方自增
        n >>= 1;                  // 指数减半
    }
    return r;
}
```
（迭代版即"减而治之的对半"：每轮把指数砍半、底数平方——偶数直接半，奇数削 1 再半。）2^10^18 mod 1e9+7 约 60 轮出结果。RSA 的加密/解密就是这个函数在大数上的调用。

## C2 参考

```cpp
int lcsMemo(const std::string& s, const std::string& t, int i, int j, std::vector<std::vector<int>>& memo) {
    if (i == (int)s.size() || j == (int)t.size()) return 0;
    if (memo[i][j] >= 0) return memo[i][j];
    return memo[i][j] = (s[i] == t[j])
        ? 1 + lcsMemo(s, t, i + 1, j + 1, memo)
        : std::max(lcsMemo(s, t, i + 1, j, memo), lcsMemo(s, t, i, j + 1, memo));
}
```
1. 朴素递归 20 字符：调用数可达 **10⁶~10⁷ 级**（最坏 2^(m+n) 的形态）
2. 记忆化：每 (i,j) 只算一次，≤ 21×21 次真实计算
3. 迭代版：双重循环 i 从大到小、j 从大到小填表——fib 的一维滚动升级为二维表。
（LCS 是 diff/git 差异比较的核心算法。）

## C3 参考

行优先 vs 列优先同为 O(n²)，实测差数倍——"每次访存 O(1)"在缓存层级（L1/L2/L3/内存差一个数量级以上）面前不成立。但复杂度分析依然有用，因为它回答的是**阶级问题**：O(n²) 无论怎么磨常数都追不上 O(n log n) 在大 n 下的差距（463 天 vs 秒级）。两层分工：**Big-O 选路（战略），常数/访存磨刀（战术）**——后者正是超算比赛的主战场，而前者是参赛资格。
