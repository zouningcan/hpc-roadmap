# 模块 09 答案：词典与散列

## A 概念题

**A1** 比较树视角：n 个候选每次比较分两支，二叉判定树高 ≥ log₂n——**只要决策靠"比较"，信息量上限就锁死对数**。散列的突破靠两样：① **算术代替比较**（hash 直接算位置，跳过逐个排除）；② **冗余空间**（M > n，λ<1，给每个键预留位置）。代价：空间开销 + 冲突处理复杂度 + 失去有序性。

**A2** 
- M=7：12→5，25→4，33→5（**与 12 冲突**），47→5（**又与 33 冲突**）
- M=8：12→4，25→1，33→1（冲突），47→7
反例说明：12 与 33 差 21，21 mod 7 = 0 → **凡差是 M 约数的键永远同桶**——M=7 时所有 7 的倍数间隔的键扎堆。素数的约数只有 1 和自己，等差数列（差非 M 倍数）才能铺满全表。M=8（2³）时偶数键全落偶数桶——一半的桶永远空着。

**A3** 直接清空会**截断探测链**：场景——10 与 17 都 hash 到桶 3（M=7）：17 探测落桶 4；现在删 10（清空桶 3）；查找 17：算出桶 3，**空 → 判定"不存在"**——但 17 明明在表里桶 4。删除破坏了"空桶=查找终点"的前提。懒惰删除：打 DELETED 标记，查找跳过继续探测。

**A4** 聚集的自我强化：连续占用段越长 → 新键的探测路径**碰上这段的概率**越大（路径是连续区间）→ 一旦碰上就撞到底再往后接 → 段更长。平方探测打断机制：偏移 1,4,9,16... 不再连续，冲突后**跳离**聚集段；且保证 M 素数、λ≤0.5 时前 ⌊M/2⌋ 次探测必命中空位（存在性定理）——**0.5 是平方探测的保命线**，超了可能探不完一半桶就循环。

**A5** 位数组查询的语义是"k 个位全 1 = 大概率插入过"：插入过的串置的 k 位必然仍全 1（除非被别人覆盖——只可能把 0 变 1，不会 1 变 0）→ **绝无误判"不在"**；反之 k 位全 1 可能是多个不同串的位**叠**出来的 → 有假"在"。适合：缓存穿透防护（不存在的键直接拒绝查库）、爬虫去重、恶意地址黑名单——**前置粗筛，承受小概率误报换十倍查询提速**。

## B 动手题

**B1** 骨架：
```cpp
struct HashMap {
    static const int M = 101;
    vector<list<pair<int,int>>> buckets{M};
    int h(int k) { return k % M; }
    void put(int k, int v) {
        for (auto& p : buckets[h(k)])
            if (p.first == k) { p.second = v; return; }
        buckets[h(k)].push_back({k, v});
    }
    int get(int k) {                       // 不存在返回 -1
        for (auto& p : buckets[h(k)])
            if (p.first == k) return p.second;
        return -1;
    }
    void remove(int k) {
        buckets[h(k)].remove_if([k](auto& p){ return p.first == k; });
    }
};
```
20 键入 101 桶，λ≈0.2，每链期望 <1 个节点——全部操作应该秒出。

**B2** 关键代码与验证：
```cpp
static const int EMPTY=-1, DELETED=-2;
vector<int> key{M, EMPTY}, val{M};
int find_slot(int k) {                    // 查找/插入共用探测
    int i = h(k), first_del = -1;
    for (int j = 0; j < M; j++, i = (i+1)%M) {
        if (key[i] == k) return i;                        // 命中
        if (key[i] == DELETED && first_del < 0) first_del = i;  // 记录可复用位
        if (key[i] == EMPTY) return first_del >= 0 ? first_del : i;  // 空=链尾
    }
    return first_del;
}
void erase(int k) { int i = find_slot(k); if (i>=0 && key[i]==k) key[i] = DELETED; }
```
懒惰删除版：get(221) 从桶 10（DELETED，跳过）继续 → 桶 11 命中 ✓。真清空版：桶 10 为 EMPTY，探测终止 → get(221) 返回 -1 ✗——**亲手复现探测链断裂**。

**B3** 参考结果（λ=0.9，M=1009，n=908）：
| 策略 | 平均成功探测次数（理论） | 实测量级 |
|------|--------------------------|----------|
| 线性探测 | 1/(1-0.9)²/2 ≈ 50 | 30-60（聚集重） |
| 平方探测 | ~1/(1-0.9) = 10 | 8-12 |
| 双散列 | ~10 | 7-10 |
差异一个数量级——聚集的实锤。结论：λ 大时**策略选择直接决定 5-10 倍性能**。

**B4** 滚动更新核心：
```cpp
unsigned long long h = 0, pow_m = 1;
for (int i = 0; i < m; i++) h = h*131 + s[i];          // 初始窗口
for (int i = m; i <= (int)s.size(); i++) {
    if (h == hash_t && s.compare(i-m, m, t) == 0) hit(i-m);  // 散列相同再比较（防碰撞）
    if (i < (int)s.size()) h = (h - (unsigned long long)s[i-m]*p_m1)*131 + s[i]; // 滚动
}
```
（p_m1 = 131^(m-1)。）匹配处仍要做 O(m) 真比较（防假阳性），但比较只发生在散列相等处——随机数据下期望 O(n+m)，比暴力 O(n·m) 快一个量级。这就是 **Rabin-Karp**。

## C 挑战题

**C1** 参考实现要点：`if (count*2 > M) rehash(next_prime(M*2));`，rehash 把所有活元素按**新 M** 重新散列（旧桶号作废）。曲线预期：**锯齿状**——大部分插入 O(1) 平底，rehash 时一根 O(n) 尖峰；尖峰间隔翻倍（M×2），高度翻倍但均摊每元素 O(1)。这是 vector 扩容的同款均摊故事（stage2 模块 02 呼应）。

**C2** 理论误报率：k=3, n=1000, m=8192 → kn/m ≈ 0.366 → (1-e^-0.366)³ ≈ 0.049 ≈ **5%**。实测应在 3-8% 区间。调参直觉：误报率只随 kn/m 变——**n 涨一倍，m 也得涨一倍**才能保住误报率；k 不是越大越好（最优 ≈ 0.693·m/n）。

**C3** 骨架：
```cpp
unordered-free 实现：
vector<vector<int>> group(256);              // 价格 mod 256 落桶
for i in N: group[price[i]].push_back(i);
for 每组:
    map<末16B散列, 代表下标> seen;            // 粗筛：末16B 的散列 → 已保留条目
    for j in 组内（按魔咒号序）:
        if seen 无同散列 → 保留，seen[散列]=j
        else → 与该散列对应的保留条目做"异或字符数≤3?"细比
```
瓶颈：组内两两比较 O(组大小²)。末 16B 散列粗筛把"必须细比"的对手压缩到**散列碰撞者**——若末 16B 随机，同一散列桶期望只有常数个对手，两两比较从平方掉到线性。**粗筛（便宜的不变量）→ 细比（贵的全量比较）**是大规模去重的标准两级套路——与 Rabin-Karp 的"散列相同才比较"同宗。
