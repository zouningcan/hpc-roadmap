## 0. 一句话定位

优先级队列（priority queue）= **按"优先级"而非"先来后到"出队的队列**。ADT 只有三个核心操作却支撑了堆排序、Dijkstra、Huffman、操作系统调度——本章学它的标准实现：**堆（heap）**。

## 1. ADT 与朴素实现的困境

| 操作 | 语义 |
|------|------|
| `insert(e)` | 插入元素 e |
| `getMax()` | 看最高优先级元素 |
| `delMax()` | 取出最高优先级元素 |

朴素实现各有短板（这是"为什么需要堆"的推导）：

| 实现 | insert | delMax | 病 |
|------|--------|--------|-----|
| 无序向量 | O(1) | O(n) | 删的时候要扫全表 |
| 有序向量 | O(n) | O(1) | 插的时候要挪屁股 |

**堆：两个操作都 O(log n)，取中间路线。**

## 2. 完全二叉堆（complete binary heap）

**形状**：完全二叉树（除最底层外全满，底层从左到右排列）→ 可**压缩成数组**存（父子下标互算，零指针）：

```
树视图              数组视图（下标从 0）
        A                  [A B C D E F]
      B   C        i 的 parent = (i-1)/2
     D E F         i 的 lchild = 2i+1, rchild = 2i+2
```

**堆序性（heap-order）**：任一节点 ≥ 其孩子（大顶堆 max-heap）——注意**只约束父子，不约束兄弟**，所以"堆不是完全有序的"，找最小值仍要 O(n)。

### 2.1 插入：上滤（percolate up）

新元素追加到数组末尾（保持形状），然后与 parent 比较冒泡上浮——最多走树高 O(log n)。

```cpp
void percolateUp(int i) {
    while (i > 0) {
        int p = (i - 1) / 2;
        if (_elem[p] >= _elem[i]) break;
        swap(_elem[p], _elem[i]);   // 严格实现：先只挪 parent，最后落位（减少交换次数）
        i = p;
    }
}
```

### 2.2 删除最大：下滤（percolate down）

拿**最后一个元素**补到堆顶（形状保持），然后与**较大**的孩子交换下沉——O(log n)：

```cpp
void percolateDown(int i, int n) {
    while (true) {
        int l = 2*i + 1, r = l + 1, big = i;
        if (l < n && _elem[l] > _elem[big]) big = l;
        if (r < n && _elem[r] > _elem[big]) big = r;
        if (big == i) break;
        swap(_elem[i], _elem[big]);
        i = big;
    }
}
```

🕷 与较大孩子比（不是任一孩子），否则换完仍违反堆序——下滤 bug 第一名。

### 2.3 建堆：Floyd 自上而下下滤，O(n)

从**最后一个内部节点**（下标 n/2 - 1）倒着逐个下滤——线性时间。为什么不是 O(n log n)：高度为 h 的节点只有 n/2^(h+1) 个，总代价 Σ(h·n/2^(h+1)) = O(n)。

🕷 **经典考题**：逐个 insert（n 次 percolateUp）是 O(n log n)；Floyd 建堆 O(n)。两者结果**都合法但不一定相同**。

## 3. 堆排序（就地版）

建堆 O(n) 后，反复"堆顶与末位交换 → 规模减一 → 下滤"，n-1 轮 O(n log n)，原地完成——`09` 排序章的正式主角，此处先见整型。

## 4. 多实例与左式堆（mergeable heap）

**问题**：两个堆要合并（merge），普通堆只能"小堆逐个插入大堆" O(m log(n+m))——堆的天生弱项（数组布局不认树指针）。

**左式堆（leftist heap）**：二叉树 + **堆序性 + 左倾性**——每个节点"左子树 NPL ≥ 右子树 NPL"（NPL = null path length，到最近外部节点的距离）。合并算法：沿右脊递归合并，回溯时若右子 NPL 大就交换左右——merge/insert/del 全部 O(log n)，**以右侧变瘦为代价换高速合并**。

考试深度：会推导 NPL 不变量、手画两次 merge 即可；Fibonacci 堆（insert/merge O(1)，均摊）知概念即可。

## 5. 常见误区清单

1. 堆 ≠ 排好序的数组：堆序只管父子线，兄弟间、跨子树间无序——`getMin` 仍要 O(n)（大顶堆）
2. 上滤/下滤方向搞反：插入上滤、删除下滤——记忆：**新来的往上问家长，补位的往下找位置**
3. 建堆从下标 0 开始逐个下滤：错——要从**最后一个内部节点**倒序
4. 左式堆"左倾"想当然认为左边更高：恰恰相反，**右侧路径短**（NPL 不变量逼着树往左歪）
5. 用堆实现"队列+优先级"忘了稳定性问题：同优先级元素出队次序未定义——需要稳定语义得附加时间戳

## 6. 与超算比赛的联系

- 事件驱动模拟（RopeNet 碰撞事件）的待处理事件集 = 优先级队列
- 任务调度器（Slurm 的内部工作集、OS 就绪队列）本质是优先级队列——模块 01 的概念在数据结构层的根
- 限制条件下的 TopK（流式数据前 K 大）：维护 K 大小的**小顶堆**，O(n log k)——OJ 常客
