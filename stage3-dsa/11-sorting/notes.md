## 0. 一句话定位

排序 = **把逆序对消灭到零的过程**。所有比较排序的复杂度，都由"每一步能消多少逆序对"决定——用这一把钥匙能开所有算法的门。

## 1. 总览战报（背熟这张表）

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 一句话本质 |
|------|------|------|------|------|-----------|
| 冒泡 | O(n²) | O(n²) | O(1) | ✅ | 相邻逆序对逐个消 |
| 插入 | O(n²) | O(n²)（逆序输入） | O(1) | ✅ | 新牌插进有序手牌（基本有序时 O(n+逆序数)！） |
| 选择 | O(n²) | O(n²) | O(1) | ❌ | 每轮选最小归位（交换破坏稳定性） |
| 归并 | O(n log n) | O(n log n) | O(n) | ✅ | 分治 + 线性合并，**稳定界的王者** |
| 快排 | O(n log n) | O(n²)（已序+烂 pivot） | O(log n)栈 | ❌ | 分治 + 原地划分，实践最快 |
| 堆排 | O(n log n) | O(n log n) | O(1) | ❌ | 建堆 + n 次 delMax（模块 08 出品） |
| 希尔 | ~O(n^1.3) | 视步长序列 | O(1) | ❌ | 带步长的插入排序——**跳跃式提前消大逆序** |
| 计数 | O(n+k) | O(n+k) | O(k) | 可稳定 | 键域小直接开桶数数（**非比较，破下界**） |
| 基数 | O(d(n+k)) | 同左 | O(n+k) | ✅ | 逐位做稳定计数排序（LSD 从低位起） |

## 2. 比较排序的下界：为什么 O(n log n) 是天花板

n 个元素的排序结果有 n! 种，每次比较二分一分 → 判定树高 ≥ log₂(n!) ≈ n log n（Stirling）。**归并/快排/堆排已经贴着天花板**——再想快只能**不用比较**：计数/基数排序靠"键的额外结构"（小整数域、位数有限）绕过判定树。

## 3. 三大分治的对照（考试的常客）

- **归并**：先分到底再合；合并两有序段是 O(n) 双指针扫——**稳定但费空间**；对链表排序（stage2 模块 11）天然契合（不需要辅助数组）
- **快排**：先划分后递归；partition（pivot 归位，左小右大）是灵魂——**原地但最坏 O(n²)**；工程优化三连：三者取中选 pivot / 小段切插入排序 / 递归浅侧尾递归
- **堆排**：建堆 O(n) + n 次 delMax；**最坏 O(n log n) + O(1) 空间**的双冠王，但缓存局部性差（跳跃访存）——实践常输给快排

🕷 快排最坏情形：**已有序数组 + 取首元素为 pivot** → 划分一边倒 → O(n²)。随机取 pivot 或三者取中是对策。

## 4. 稳定性：为什么有人在乎

稳定 = 相等键保持原相对次序。单排整数看不出差别；**多关键字排序时它是命**：先按"系"排、再稳定按"分"排 → 同分内自动按系有序。基数排序整个架构就压在"每一趟必须稳定"上。

## 5. 希尔排序：插入排序的加速度版

按步长 gap 分组做插入排序，gap 逐轮减半到 1——**大 gap 时可以一次跳很远消大逆序**，最后 gap=1 时数组已基本有序（插入排序在近有序输入上是 O(n)）。复杂度依赖步长序列（Shell 原始 O(n²) → Hibbard 2^k-1 → Knuth 3h+1 → Sedgewick…）——**分析至今未完全解决**的排序。

## 6. 外排序（延伸——HPC 真正用到的排序）

内存装不下时的排序：**生成有序归并段（runs）→ 多路归并**。k 路归并一次选最小 = 败者树/堆（模块 08 再出场）。排序的总 IO 次数 ∝ 归并趟数 = log_k(段数)——**加大 k（多路）或少写盘（置换选择生成更长段）是外排序的全部艺术**。Graph500 排序 kernel 的分布式版本 = 外排序的并行化（各节点排自己的，再跨节点归并/采样划分）。

## 7. 常见误区清单

1. "O(n log n) 已最优"只对**比较排序**成立——计数/基数靠键结构突破（但键域大了就不划算）
2. 插入排序"慢"是平均印象：**近有序输入上它是最快的 O(n)**——工程里混合排序（Timsort/Introsort）拿它收尾小段
3. 快排选首元素当 pivot 拿去跑已序数据：O(n²) 事故现场——随机/三者取中
4. 选择排序假装自己稳定：交换远程元素会**跳过**相等元素——稳定性卒（除非用插入式归位）
5. 堆排"总是最优"：最坏 O(n log n)+原地没错，但**缓存不友好**让它实践输给快排——理论与工程的两套标尺
6. 基数排序 LSD 从**高位**开始：错——必须从低位，且每趟稳定，否则前趟排序被后趟洗掉

## 8. 与超算比赛的联系

- 排序是**并行算法的试金石**：归并可并行（分段排+多路归并=04 模块 MPI 范式）、快排可并行（划分后两侧递归并行=03 模块 task）
- **Graph500 的排序 kernel**：分布式排序考的是"各节点排序 + 跨节点划分"——外排序思想的集群版
- HPC 排序库（如 NSYS 计时内的 radix sort）常用**基数排序**：无比较、可向量化、确定性访存——GPU 排序的标准答案（模块 07/05 的呼应）
