# 模块 11 答案：排序

## A 概念题

**A1** 插入排序的代价 = 逆序对数：基本有序 → 逆序对少 → 每次插入只挪一两步 → O(n+逆序数)。快排取首为 pivot 在已序输入上：每次划分把 pivot 放在最边上、两边一边倒 → 递归深度 n → O(n²)。**插入怕乱不怕序，快排（烂 pivot）怕序不怕乱**——方向相反。

**A2** n! 种排列作为判定树叶，二叉判定树高 ≥ log₂(n!) ≈ Ω(n log n)——比较一次最多二选一。计数排序绕开法：**不比较，直接把键当数组下标数个数**（开桶）。代价：需要键域有限且不大（O(k) 空间）、丢通用性（浮点/长串不适用）。

**A3** 表见 notes 第 1 节。双约束筛选：稳定 ✅ 且最坏 O(n log n) ✅ → **归并排序**（快排不稳、堆排不稳；堆排和归并都 O(n log n) 但只有归并稳定）。

**A4** 从低位趟：设已按个位分好组（第一趟稳定排序），第二趟按十位稳定排序时，**同十位的元素个位序不被打乱** → 自然有序。手工 `{25,14,21,15}`：第一趟（个位）：4 桶：14；1 桶：21；5 桶：25,15 → `14,21,25,15`；第二趟（十位稳定）：1 桶：14,15；2 桶：21,25 → `14,15,21,25` ✓。若从十位先排，个位趟会把十位序洗掉（不稳定时）——**低位起 + 每趟稳定**缺一不可。

**A5** 趟数 = log_k(段数)：k 越大趟数越少、读盘量越少；但每选一个最小值要在 k 个候选里比——朴素比较 O(k)。堆（小顶）把"k 选 1"降到 O(log k)——每趟归并总代价 O(记录数·log k)。败者树是堆的 tournament 优化版（更少比较次数）。

## B 动手题

**B1** 三实现要点：冒泡早停——某轮无交换即有序（swap 标志）；插入——`for i: t=a[i]; for j=i-1; j>=0 && a[j]>t; j--` 后 `a[j+1]=t`；选择——每轮选最小与 i 交换。`{5,2,9,1,5,6}` 逆序对数：手工数 = 8（(5,2)(5,1)(2,1)(9,1)(9,5)(9,6)(5,1)(5,6 不算…实际 5,6 是正序)）——插入排序打印的移动总数应恰为逆序对数（每个移动消一个逆序对）。

**B2** 递归版骨架：
```cpp
void mergeSort(int* a, int lo, int hi, int* buf) {   // [lo, hi)
    if (hi - lo < 2) return;
    int mi = (lo + hi) / 2;
    mergeSort(a, lo, mi, buf); mergeSort(a, mi, hi, buf);
    // 双指针合并 a[lo,mi) 与 a[mi,hi) 到 buf，再拷回（取等号时先取左→稳定）
}
```
迭代版：`for (width=1; width<n; width*=2) for (lo=0; lo<n; lo+=2*width) merge(...)`。
链表 O(1) 额外空间：合并只需改 next 指针，节点不动——**拼接即合并**，无需缓冲数组。

**B3** 要点：
```cpp
int median3(int* a, int lo, int hi) {   // 三者取中：把中位数放 hi-1 作 pivot 岗
    int mi = (lo + hi) / 2;
    if (a[mi] < a[lo]) swap(a[mi], a[lo]);
    if (a[hi-1] < a[lo]) swap(a[hi-1], a[lo]);
    if (a[hi-1] < a[mi]) swap(a[hi-1], a[mi]);
    return a[hi-1];
}
// partition：pivot 移到 hi-1，双指针向中间夹；区间 < 16 交插入排序收尾
```
预期实测：随机输入两者同量级；已序输入——取首 pivot 退化到数秒级（O(n²)，n=1e5 时 ~10¹⁰ 操作），三者取中正常毫秒级。**亲眼看一次退化，比背十遍复杂度表有用**。

**B4** 参考量级（1e6 随机 int）：快排 ~90ms、归并 ~120ms、堆排 ~250ms。堆排慢的原因：下滤在数组里**跳跃访存**（0→2→6→14…父子下标跳跃跨缓存行），快排/归并的扫描是顺序访存——**缓存行命中率**的差别。理论复杂度相同，微架构代价不同——理论与工程的分野（HPC 视角此课必上）。

## C 挑战题

**C1** 稳定计数排序骨架：
```cpp
// cnt[key]++ → 前缀和 → 逆序遍历原数组放入输出位置（逆序=稳定的关键！）
for (i = n-1; i >= 0; i--) out[--cnt[key[i]]] = a[i];
```
LSD 基数：4 趟，每趟按 (v >> 8k) & 0xFF 做稳定计数排序。预期：1e6 的 4 趟基数 ~80-150ms，可与快排打平或更快——**无比较、访存模式确定、可预取**；键域/位数受限期数据越大基数越香（这也是 GPU/分布式排序选 radix 的原因）。

**C2** Knuth 步长生成：`h = 3h+1` 直到 >n/3 再倒序使用。预期：希尔 ~25ms vs 插入排序 ~4s（n=1e5 随机）。"不白费"的原因：大 gap 趟的一次交换能跨很远地消掉**大量**逆序对（gap 越大，单次交换消的逆序对期望越多）；小 gap 趟接手时数组已"宏观有序"（每个元素离最终位置不远）——插入排序在近有序输入上恰是 O(n)（A1 的结论在这里变现）。各趟不是重复劳动，是**接力递降的逆序对清理**。

**C3** 
1. 1024MB / 100MB → **11 段**（最后一段不满）
2. 4 路归并：趟数 = ⌈log₄11⌉ = 2 趟；每趟读+写全量 ≈ 2GB×2 趟 = 总读盘 ~2GB（写盘同量）
3. k 大：趟数 log_k(段数) 下降（64 路只要 1 趟）——省 **IO**；费的是每记录选择的比较成本（朴素 O(k)）→ **堆/败者树 O(log k)** 解决，k 可以开很大——外排序的全部艺术就是把趟数压到 1-2，全靠"多路 + 优先级队列选路"。（Graph500 分布式排序同款：各节点内排好 + 跨节点采样划分/多路归并。）
