# 模块 01 参考答案：集群与 Slurm

## A 概念题

**A1** a) 登录节点：ssh 进去的入口，只做编辑、编译、提交、看结果；计算节点：真正跑计算的机器，由调度器分配，不能直接 ssh。b) ①登录节点是全体用户共享的少数几台，你跑重活会占满 CPU 拖慢所有人的编辑/编译/提交；②它不是为计算设计的（无高速互联、无大内存配额），作业本身也跑不好，管理员用进程清理脚本杀重负载是标准操作。

**A2** a) 上百用户抢上千核：谁先用、用多久、用多少、怎么记账——调度器统一排队分配，避免抢占冲突。b) sbatch = 提交脚本排队跑（正式作业）；srun = 申请资源立即运行一条命令（短测试/交互程序）；salloc = 只借资源，给你一个落在计算节点上的交互 shell（调试编译环境、试命令）。

**A3** a) bash 眼里它是**注释**（# 开头，直接跳过）；b) Slurm 在 sbatch 提交时扫描这些行，当**作业参数**收走（等价命令行选项）。c) 只分到默认的 1 核，多线程全部挤在一个核上空转，速度不升反可能降——**核是申请来的，不是默认给的**。

**A4** module 管理多版本编译器/库/MPI 共存的环境。`module load gcc/11` 底层是修改当前 shell 的环境变量（把该版本的 bin 挂进 PATH、库路径挂进 LD_LIBRARY_PATH 等）。sbatch 作业启动的是**干净环境**，不继承你交互 shell 里 load 过的模块，所以脚本里必须重新 load。

## B 动手题

**B1** 参考脚本：
```bash
#!/bin/bash
#SBATCH -J graph500
#SBATCH -p kp_run
#SBATCH -N 1
#SBATCH -n 1
#SBATCH -c 128
#SBATCH -t 00:40:00
#SBATCH -o g500_%j.out

module purge
module load compiler/gcc    # 按平台实际模块名调整
make
./graph500_reference_bfs_sssp 18
```
评分点：-p kp_run（正式跑）、-c 128（吃满）、-t ≥40min 内外合理（按题面 40min 强杀上限，写 00:40:00 贴线，稳妥可写更少）、-o 带 %j、先 module 后 make。

**B2** 逐行：shebang；作业名 wrf；**队列选了 kp_interact（错①：正式跑应 kp_run）**；1 节点；1 任务；**每任务 4 核（错②：WRF 要 128 核，4 核跑 12 分钟的算例会严重超时）**；时限 1 小时（若核数对了，运行 12 分钟足够，但当前 4 核下必然超时被杀）；输出 wrf.log（能用但没带 %j，重跑会覆盖）；进入运行目录；执行。

**B3** 等价：脱离终端存活（nohup 免疫 SIGHUP ≈ sbatch 作业由调度器托管，ssh 断线不死）；输出落文件（job.log ≈ -o 的输出文件）；后台运行不占交互终端。不等价：没有资源申请（用的是登录 shell 所在机器的"野生"CPU，不是被分配的计算节点核）、没有排队（无 squeue 可言）、没有时限与记账（不会 40min 强杀、没有 sacct 流水）、不隔离环境。结论：**sbatch = nohup 的"集群豪华版"——多了资源申请、排队、限额、记账**。

## C 挑战题

**C1**
1. WRF：编译部分并行度不高 → 题面明说可以在 kp_interact 测；正式运行 wrf 必须进 kp_run。Graph500：跑分作业用满 128 核的机器（正式资源）。
2. `-N 1 -n 1 -c 128`：1 台节点、1 个任务、每任务 128 核——单机吃满。
3. WRF：编译限 60min（-t 01:00:00 段）、运行限 20min（-t 00:20:00 段）、评测总时限 20min；Graph500：40min 强杀（-t 00:40:00）。
4. 评测方要**从你的脚本的标准输出里读 TEPS 成绩**——你若重定向/修改输出，评测管道读到的是空或假数据，无法评分（且属于违规：变相篡改成绩）。

**C2**
1. `ssh-keyscan armlogin.hpc.sjtu.edu.cn | ssh-keygen -lf -`（keyscan 抓主机公钥，管道喂给 ssh-keygen 算指纹；`-` 表示从 stdin 读）。在已知无毒网络做——keyscan 本身不验证对方身份。
2. `l` = 列出公钥的指纹（fingerprint），`f` = 指定输入文件（这里是 `-` 即标准输入）。
3. 是同一个东西：首次 ssh 时显示的 fingerprint 就是主机公钥的哈希摘要（TOFU——trust on first use，首次信任）。平台让你报指纹而不是贴公钥全文，因为①指纹短、可比对（防抄错防篡改）；②证明你真的连上过正确的主机、看到了它的密钥——这是防中间人（MITM）的验证动作，也证明你会用 ssh。
