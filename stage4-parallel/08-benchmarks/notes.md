## 0. 一句话定位

基准（benchmark）= **给整台集群打分的标准化考题**。HPL 考"理论算力能兑现多少"，HPCG 考"真实负载下还剩多少"——比赛的分数榜和调优功力都在这两张卷子上。

## 1. HPL（High Performance Linpack）

**任务**：解一个超大规模稠密线性方程组 Ax=b（高斯消元），报告**每秒浮点运算次数（FLOPS）**。

- **公式**：`Rpeak = 核数 × 频率 × 每周期浮点数 × 向量单元数`；`效率 = Rmax/Rpeak`（HPL 实测/理论峰值，好集群 70-90%）
- Top500 榜单就是按 HPL 排的——**超算界的"高考"**
- 计算特征：O(n³) 计算 / O(n²) 数据 → 算术强度 O(n)，**天然的 compute-bound**——所以它测的是"机器的算力上限"，也是"调优功力的上限"

### 1.1 HPL.dat 关键参数（调优即改这四样）

| 参数 | 含义 | 调优口径 |
|------|------|----------|
| **N** | 矩阵阶数（问题规模） | 让内存占用 80-90%：`N ≈ sqrt(总内存字节 × 0.8 / 8)`；取 NB 的整数倍 |
| **NB** | 分块大小 | 对齐 BLAS 库最优块（常见 192/224/256，厂商推荐优先）；ARM 平台实测 32-256 |
| **P×Q** | 进程网格（行×列），P·Q = 总进程数 | **接近方形**（4×8 优于 2×16）；P ≤ Q |
| 次要 | PFACT/RFACT（面板分解）、NBMIN、NS、交换算法（binary-exchange / spread） | 网格扫参实验的原料 |

**调优方法论**：先算出理论 N → 固定其他扫 NB → 固定最优 NB 扫 P/Q → 最后微调 N。**每次只动一个参数**（模块 02 的单变量纪律在基准调优的原样复用）。

### 1.2 HPL 的软件栈

```
HPL ─→ BLAS（矩阵乘/三角解算的原语） ─→ 硬件
        ↑ 谁的 BLAS 谁定生死：OpenBLAS / AMD AOCL(BLIS) / Intel oneMKL / 华为 KML
```

**换 BLAS 库 = HPL 调优的最大单笔收益**（不同厂商库在自家硬件上有 10-30% 差距）——TOP500 第 3 名 Aurora 用 oneMKL、El Capitan 用 AMD BLIS，正是这个逻辑。

## 2. HPCG（High Performance Conjugate Gradient）

**任务**：共轭梯度法解大型稀疏对称正定方程组（含稀疏矩阵向量乘 SpMV、对称 Gauss-Seidel 平滑、多重网格预条件）。

- 为什么要有它：HPL 的稠密 GEMM 是"理想负载"——现代真实应用（稀疏迭代）吃**内存带宽**。HPCG 实测性能通常只有 HPL 的 **1-3%**——它才是"真实科学计算的天花板"
- 优化方向与 HPL 相反：**不是堆算力，是访存模式**（CSR 布局、并行化 SpMV、减少同步）——模块 10 的 CSR 在这里登场
- 竞赛地位：SC/ISC 把 HPCG 纳入计分正是为了"防 HPL 刷分"——两榜差距大的机器 = 算力纸面强、真实负载弱

## 4. 评测方法论（比赛里的"怎么跑出高分"）

1. **先对再快**：正确性校验（HPL 的残差检查 `||Ax-b||/||x||||A||||b|| < 1e-10` 级）不过 = 零分——所有优化前先跑通小规模参考
2. **环境冻结**：调优期间锁定频率/绑核/库版本——变量一多结论作废
3. **扫参自动化**：写脚本批量跑 HPL.dat 组合、收集 Rmax 排序（Graph500 题的 graph.sh 就是这个形态的小号）
4. **计时段只算计时段**：HelloHPC 规则第 4 条（不许把计算挪出计时区）——基准的计时语义是契约
5. **功耗墙下的权衡**（ASC/SC 决赛）：3000-5000W 约束下"频率 vs 核数 vs 节点数"是三元规划题——跑分榜 = 性能/瓦特的优化

## 5. 常见误区清单

1. N 拉满到内存 100%：溢出/交换反而暴跌——**80-90% 是甜区**（要给通信缓冲留地）
2. P×Q 随便设：非方形网格通信不均衡——P≈Q 起步
3. 只调 HPL.dat 不换 BLAS：软件栈才是大头——先确认用的是最优 BLAS
4. HPCG 用 HPL 思路调：算力导向 vs 带宽导向，药方相反
5. 评测不看正确性输出：HPL 残差超限直接判 0——比赛里"跑得快"之前先"跑得对"
6. 小规模扫参结论直接推大规模：NB 最优值随规模/网格变化——**最终验证必须在实际规模上跑**
