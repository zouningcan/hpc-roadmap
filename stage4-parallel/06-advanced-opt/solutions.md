# 模块 06 答案：进阶优化

## A 概念题

**A1** 加速比 = 1/((1-0.8) + 0.8/4) = 1/(0.2+0.2) = **2.5×**（不是 4×——其余 20% 拖后腿）。所以向量化之前必须**剖析**：先确认热点占比高、且热点可向量化（否则收益被 Amdahl 吃光）。

**A2** `v`=vector、`mla`=multiply-accumulate（乘加）、`q`=128 位、`f32`=float32 通道。`vmlaq(c, a, b)` 直接算 `c += a*b` 用 **FMA（融合乘加）硬件单元**——比 vmul+vadd 少一次中间寄存器写回、少一次舍入（精度还更好）。FMA 是现代 CPU/GPU 算力的主要来源之一。

**A3** 对应"指针可能重叠"（aliasing）：`c[i] += a[i]` 中若 c 与 a 是同一段内存，向量化后读写顺序变化会错。`__restrict` 承诺"这个指针是访问该内存的唯一途径"（无别名）——编译器敢向量化。撒谎（实际重叠）→ 编译器按不重叠生成的代码读旧值 → **结果静默错误**。

**A4** 表有 M=101 项 ≈ 808B（若存 double 6.5KB），看似全进 L1——但 1e8 次访问若与其他数据流（大数组扫描）竞争缓存，表+数组的工作集超出 L1/L2，表被反复逐出 → 每次访问从内存拿。**查表把算术换成访存，访存恰好是贵的那件事时反亏**——用 perf stat 的 cache-miss 判别。

**A5** Bitmatrix 要"按列统计 1 的个数"：整行 uint64 的 popcount 一次算 64 位——`__builtin_popcountll` 编译成单条 `cnt`（ARM）/`popcnt`（x86）指令。验证文化：向量化是否发生、用了哪条指令，godbolt 汇编里一眼可见（找 `vcntq`/`vpopcntq`）——**猜 100 次不如看一眼汇编**。

## B 动手题

**B1** 预期：
- c1：三档全向量化（最简单模式）
- c2：全失败——`a[i] += a[i-1]` 是循环携带依赖，第 i 步要用第 i-1 步的新值，SIMD 的并行通道互相不知道
- c3：跨步（结构体里 1/6 的字段有用）通常失败或低效；SoA 改写（6 个独立数组，取 vx/vy/vz 三个）恢复连续 → 向量化成功
c2 三行说明：SIMD 要求 4 条通道独立；前缀和第 i 步依赖刚算完的第 i-1 步；除非换并行前缀和算法（scan，模块 05 的 Blelloch）——那已经超出自动向简化的能力。

**B2** 预期排序：③ 查表 ≈ ② popcountll > ① 朴素（慢一个数量级以上）。②编译成单条指令（-march 开启后），吞吐 ~1 指令/周期；①逐位 64 次循环；③查表每 2 字节一次内存访问——表 64KB 出 L1 后被访存拖累，实测可能与②打平甚至更慢。**结论：内建指令到位时，查表并不总赢——量了才知道。**

**B3** NEON 版：
```c
#include <arm_neon.h>
void add_neon(const int32_t* a, const int32_t* b, int32_t* c, int n) {
    int i = 0;
    for (; i + 4 <= n; i += 4)
        vst1q_s32(&c[i], vaddq_s32(vld1q_s32(&a[i]), vld1q_s32(&b[i])));
    for (; i < n; i++) c[i] = a[i] + b[i];          // 尾循环
}
```
预期 ~3-4×：4 路并行的理论值被三件事吃掉——访存带宽（3 个数组流动）、尾循环（1024 整除 4 无损耗，但归约/其他 n 会）、装载/存储指令本身的吞吐。**4 路并行 ≠ 4×，带宽与流水才是上限**。

**B4** 参考矩阵（N=1e8 双数组，数值随机器浮动）：
| flag | 耗时 | vs -O0 |
|------|------|--------|
| -O0 | ~600ms | 1× |
| -O2 | ~180ms | ~3.3× |
| -O3 | ~120ms | ~5×（向量化参与） |
| -O3 -march=native | ~90ms | ~6.7×（FMA/更宽向量） |
| + -ffast-math | ~70ms | ~8.5×（重排/近似） |
结果不一致从 -O2/`-O3`（归约重排）就可能出现；-ffast-math 放大之。可接受条件：题目给了容差（OceanSim 1e-6/1e-4），且验证程序通过——**容差是编译器的自由度**。

## C 挑战题

**C1** 参考阶梯（N=4096，行 64×uint64）：
1. 朴素：逐位 `(row[c/64]>>(c%64))&1` 判有效行→每列逐位累加——~100ms 级
2. 无效行整体跳过 + 有效行只在 popcount 时动：有效行占比 p → 时间 ~p 倍
3. 逐列块批量：对每个 uint64 列块，预生成 64 个"列选择掩码"开销太大；更优是**转置思维**或按"行 uint64 的每 bit 位"分层累加——本题参考实现：对每个有效行、每个 uint64 chunk，把 chunk 的各 bit 分摊到 64 个计数器的开销仍是瓶颈；满分路线是**位矩阵转置一次（分治转置），之后每列变成连续 uint64 序列直接 popcount 求和**——转置 O(N²/64) 一次换后续全连续访存
4. NEON：`vcntq_u8` 对 128b（16 字节）一次数 16 字节的 popcount，`vpadalq` 累加——批量 16×
mini-writeup 范式同模块 02：症状（热点在逐位判定）→ 处方（popcount+转置+向量化）→ 疗效（逐级提速倍数）。**这道题的满分阶梯就是考试评分公式的台阶**。

**C2** AoS：每粒子 24B，6 字段中只用 3 个 float（12B）→ 每条缓存行 64B 装 2.67 个粒子，更新只用到行内一半数据但整行被搬进缓存——**有效带宽利用率 ~50%**。SoA：vx 数组连续 4B×16=64B 全是有用数据 → 利用率 100%，实测带宽常提升 1.5-2×。教训：**布局改对了，一行代码不"优化"也提速**——HPC 数据设计第一课。

**C3** 
1. 逐字节 XOR：每字节 1 次载入+异或——吞吐上限受**指令数/字节**限制（约 1-2 B/周期）
2. 8 字节一把 `u64 ^= *u64p`：指令数/字节 ÷8 → 快 ~6-8×（尾处理+装载粒度吃掉一点）。不串扰的原因：**XOR 各位独立**（没有进位/借位）——字内 8 个字节通道互不影响，天然"8 路按位 SIMD"
3. NEON veorq：128b/条 → 相对逐字节 ~16×，相对 u64 版 ~2×——理论吞吐再乘访存效率的折扣。套路名：**批量-归并（bulk then fold）**——宽操作做完，最后一步把宽寄存器的 8/16 通道折叠成单结果（与 SIMD 归约同款收尾）。
