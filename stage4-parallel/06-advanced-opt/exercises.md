## A 概念题

**A1** Amdahl 定律向量版：程序 80% 时间在一个可 4 路向量化的循环里，整体最高加速比？这解释了为什么"向量化之前必须做什么"？
*考察点：热点占比；剖析优先。*

**A2** 拆解 intrinsic 名字：`vmlaq_f32` 各段什么含义？它与 `vaddq_f32(vmulq_f32(a,b),c)` 的区别不只是少一次函数调用——还省了什么？
*考察点：NEON 命名法；融合乘加 FMA 的硬件意义。*

**A3** 自动向量化失败 Top3 里，"指针可能重叠"是哪条？`__restrict` 向编译器承诺了什么？撒谎会怎样？
*考察点：别名问题；担节的代价。*

**A4** 为什么 M=101 的查表在 1e8 次访问下可能比每次现算还慢？用缓存行/工作集语言说明。
*考察点：算术换访存的边界。*

**A5** `popcount` 在 Masked Bitmatrix 题里的角色是什么？为什么编译器/godbolt 验证"有没有向量化"比猜靠谱？
*考察点：位统计；验证文化。*

## B 动手题

**B1（自动向量化侦察）**：三个循环，分别用 `-O2`/`-O3`/`-O3 -march=native` 编译，godbolt（或 `gcc -fopt-info-vec`）看哪些被向量化：
```c
// c1: c[i]=a[i]+b[i]              （应成功）
// c2: for(i=1;i<n;i++) a[i]+=a[i-1];  （应失败——依赖）
// c3: c[i]+=s*comp[i][0]（结构体数组跨步访问）  （可能失败——gather）
```
对 c2 写一个"前缀和不可能向量化的原因"的三行说明；对 c3 给出 SoA（structure of arrays）改写再验证。
*考察点：向量化友好代码的形状；AoS→SoA。*

**B2（popcount 三种实现对决）**：统计 1e8 个 uint64 中 1 位的总数：① 朴素逐位 ② `__builtin_popcountll` 循环 ③ 查表（16bit 表）。比耗时并用 perf/godbolt 解释排序（提示：popcount 是否被编译为单条指令、查表的缓存行为）。
*考察点：位统计的三个台阶；指令 vs 访存。*

**B3（🅰 NEON 手写 or 伪代码）**：两个 int32 数组各 1024 元素求和。写标量版与 NEON 版（vld1q/vaddq/vst1q + 尾循环），① godbolt 验证生成 `vaddq` ② 无 NEON 平台写 AVX2 版对照（`_mm256_add_epi32`）③ 各自耗时对比（预期 ~3-4×，为什么不是 4×——访存+尾循环+归约）。
*考察点：intrinsics 全流程；速度上限的现实修正。*

**B4（编译 flag 矩阵）**：对 03 模块 B3 的 sum_array：
```
gcc -O0 / -O2 / -O3 / -O3 -march=native / -O3 -march=native -ffast-math
```
五档计时填表（同 baseline 对比），并回答：哪一档开始出现"结果与 -O0 不一致"？不一致的机制（结合律）与可接受条件？
*考察点：flag 的实际手感；-ffast-math 的边界。*

## C 挑战题

**C1（Bitmatrix 预演）**：HelloHPC 风格简化版：N=4096 的位矩阵（行连续，每行 64 个 uint64）+ 64 个 uint64 的掩码，统计"掩码有效行"中每一列 1 的个数。
1. 朴素版：三层循环逐位判——测 baseline
2. 优化一：先 `mask[i>>6]>>(i&63)&1` 判有效行，整行 `popcount` 跳过无效行
3. 优化二：逐 uint64 列块内 `popcountll(chunk & colmask)` 批量累加
4. 🅰 优化三：NEON `vcntq_u8` 向量化 popcount（伪代码亦可）
每步测耗时，写 mini-writeup。
*考察点：位运算+访存+向量化的组合拳——考试满分题的阶梯。*

**C2（SoA 改造）**：粒子系统 AoS 版 `struct P {float x,y,z,vx,vy,vz;}` 数组 1e7 个，更新只用 vx/vy/vz。先测 AoS 更新带宽（GB/s），改 SoA（6 个独立 float 数组）再测——解释缓存行利用率的差异（AoS 每行带走 12B 无用数据）。
*考察点：数据布局是零成本优化——不改算法只改排布。*

**C3（考试预演：m4c 的位级优化）**：魔咒 checksum = 按 byte 异或和，魔咒长 32-16384B、总量 1e6 条：
1. 朴素逐字节 XOR 的吞吐上限受什么限制？
2. 用 64 位字批量 XOR（8 字节一把）+ 收尾归并各字节，快多少倍？XOR 的什么性质保证"字内 8 字节互不串扰"？
3. 🅰 再用 NEON veorq_u8 一条 128b……计算理论吞吐倍数
*考察点：位运算的批量-归并套路——与 Bitmatrix 同源，考试必考的"位级并行"。*
