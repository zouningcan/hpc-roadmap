# 模块 02 答案：性能剖析

## A 概念题

**A1** 采样：定时抓程序计数器现场（统计近似），开销近零、不改代码——现代默认（真实负载下测真实程序）。插桩：编译/运行时在函数出入口插入计时代码，精确但开销大且扭曲时序（工具效应）。采样赢在"测量不改变被测对象"，且内核 perf_event 让它免费可用。

**A2** memory-bound。推理链：IPC 0.35 意味着 CPU 大部分周期在**等**（不是算）；cache-miss 28% 说明等的原因是数据不在缓存——指令喂不饱是因为内存喂不饱。第二组 IPC 2.1 = CPU 在真干活（每周期 2 条指令，超标量的好成绩），branch-miss 15% 高——瓶颈是**分支预测失败**（流水线被冲刷），优化方向是消分支/查表化。

**A3** x 轴是**函数名字母序**（避免时间轴抖动，同函数叠一起方便看总占比），不是时间；宽度 = 该函数在采样中的占比（时间比例）；y 轴 = 调用栈深度（越上越接近叶子函数）；最宽的塔 = 最贵的调用链——从塔底到塔尖读出"谁→谁→谁"花掉了时间。把 x 当时间轴是火焰图第一大读错。

**A4** ① **留 baseline**：优化前后必须同条件对比，否则"快了"无凭据（防自我感觉良好）；② **单变量**：一次只改一处（防功劳/罪责无法归因）；③ **重验正确性**：快的错误答案=零分（防"优化"改出 bug——OceanSim 1e-6 容差裁判）。这三条直接写进比赛 writeup 就是满分骨架。

## B 动手题

**B1** 参考：
- baseline：~2.5-4 s（1e8 次三角+开方，每次 ~20ns 级）
- perf report 预期：`sin@plt` + `cos@plt` + `sqrt` 合计 >80%
- 优化：sin·cos = sin(2x)/2（消一个函数）；sqrt(i) 用增量法 `s += 2*i+1 → s=sqrt 时…` 或直接利用 `sqrt(i) = i^0.5` 的查表/缓存——最简单合法版：
```c
double s = 0;
for (long i = 0; i < N; i++) s += sin(2.0*i) * 0.5 * sqrt((double)i);
```
省一个函数调用，~1.5-1.8×；再加 `-ffast-math`（本程序无正确性裁判）或向量化 → 数倍。mini-writeup 范例：
```
症状：perf report 显示 82% 耗时在 sin/cos/sqrt。
处方：利用恒等式 sin(x)cos(x)=sin(2x)/2 消除 cos 调用。
疗效：3.1s → 1.9s（1.6×），正确性由输出一致性验证（-O2 下与 baseline 差 <1e-9）。
```

**B2** 预期指纹：
| | IPC | cache-misses |
|---|---|---|
| A 计算密集 | 高（1.5-3） | 低（<5%） |
| B 随机访存 | 低（<0.5） | 高（20-50%） |
判型结论：A 是 compute-bound（优化方向=向量化/算法），B 是 memory-bound（优化方向=访存模式/预取/布局）。

**B3** 三病因与取证：
| 病因 | 取证 |
|------|------|
| 忘 -fopenmp | `htop` 只有一核 100%（其余空闲）；重编译加 -fopenmp 验证 |
| 线程数=1 | `echo $OMP_NUM_THREADS`（空≠1，看默认核数）；htop 仍单核忙 |
| 循环太短/负载太小 | 剖析显示 parallel 区域占比 <10%——线程创建开销吞掉收益（03 C3 知识点） |

**B4** 插桩派输出差异：gprof/callgrind 给"函数调用次数 + 每函数含子调用总耗时"（精确到次数）；perf report 给"采样占比（近似）"。插桩能看到"被调 1e8 次 × 每次 3ns"这类**次数信息**——采样派看不到次数，只看得到总占比。两者互补。

## C 挑战题

**C1** 
1. `perf stat` 预期：IPC < 0.5、cache-misses 高——跨步访存（j 变化 1 → 地址跳 W×4 字节）每 4B 数据就要新缓存行
2. report：热点在 j 内层循环的 `a[j*W+i]` 行
3. 循环交换后（i 内层：`a[j*W+i]` 中 i 连续 → 顺序访存）：cache-misses 从 ~25% 级降到 ~2% 级，耗时常见 3-10× 提速（W 大时更显著）
4. writeup 范例：`症状：IPC 0.4/cache-miss 27%，热点 j 循环跨步访存 → 处方：循环交换恢复行主序连续访问 → 疗效：4.2×提速，miss 27%→3%，输出与 baseline 逐位一致`。

**C2** 证据链（perf c2c 可用时）：c2c report 直接标出 HITM（Hit Modified）缓存行——显示 `c[0]`/`c[1]` 同一 64B 行被两个核反复写（cache-to-cache 传输次数爆表）；padding 后 HITM 归零、耗时回落。不可用时用对照实验：padding 版耗时显著低 + 唯一差异是"两变量是否同行"——排除法锁定伪共享。**要点：性能结论必须有计数器/对照实验背书**。
