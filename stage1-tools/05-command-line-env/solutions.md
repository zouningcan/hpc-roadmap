# 模块 05 参考答案

## A1

**断网 → SSH 连接断 → 集群上的 sshd 发现客户端没了 → sshd 给登录 bash 发 SIGHUP → bash 死，其子进程（任务）被清理。**
"没有任何东西重启"：被杀的是你的登录 bash（信号处决，不是崩溃也不是重启），任务作为它的子进程在进程树上陪葬。重连时 sshd 给你新开一个全新空白 bash——旧的一切都不在了。

## A2

a) SIGTERM **可被捕获**——程序能收到并在退出前保存现场、清理临时文件；SIGKILL **不可捕获不可忽略**，内核直接终结进程。
b) 先礼后兵：给程序机会做清理（半写的文件、占用的锁），大多数程序响应 TERM 就够了。
c) 已经卡死、不响应任何可捕获信号的程序（死循环且没写信号处理器），只能 SIGKILL——但代价是没机会清理，可能留下孤儿进程、临时文件、锁住的资源。

## A3

tmux 采用客户端/服务器架构：**"tmux 服务器"是真实存在的进程**（守护进程，常驻集群内存，有 PID），不是比喻。你面对的界面是**客户端**（取景器），会话与任务挂在服务器名下。断线杀死的是客户端及其所在的登录 bash 分支；服务器进程不依赖你的连接，毫发无伤。验证：脱离后 `ps aux | grep tmux` 仍能看到服务器进程行。

## A4

| 方法 | 机制 | 场景 |
|------|------|------|
| tmux | **换爹**：任务挂到 tmux 服务器下，脱离登录 bash 的进程树 | 开发调试、需要回去看/交互的任务 |
| nohup | **装死**：任务自己忽略 SIGHUP，仍挂在原处 | fire-and-forget，跑完看日志即可 |
| Slurm sbatch | **换地方**：任务由调度器安排到计算节点，与登录会话无关 | 集群上正式提交长任务（要核数/内存/时限） |

## A5

`source ~/.bashrc`（或重开终端）。本质：**当前 shell 亲自逐行执行该文件的每一行**（不产生子进程），所以里面新的别名/函数/PATH 立刻写进本 shell 的内存。对比 `bash ~/.bashrc` 只会影响子 shell、对你毫无作用。

## B1 预期现象

- `kill -TERM %1`：任务直接消失（jobs 里没了/显示 Terminated）
- `kill -STOP %2`：状态变 **Stopped**（进程还在但不跑，CPU 0%）
- `kill -CONT %2`：状态变 **Running**
- `pgrep -af sleep`：`-a` 显示完整命令行、`-f` 匹配全命令，用于确认；`pkill sleep` 全部清场

## B2

`ps aux | grep tmux` 里会看到脱离后依然存在的 tmux 进程行（通常显示为最初 `new -s work` 的调用形式）。一句话：它不依赖你的终端/连接存活——它是独立的守护进程，你的断线只影响取景器（客户端）。
（若忘记 kill-session，直接关掉所有会话后服务器进程也会随最后一个会话退出。）

## B3

Ctrl-Z 后打印 `[1]+ Stopped sleep 600`，提示符回来（进程暂停但没死，`jobs` 可见）→ `bg` 让它在后台继续跑（此时可以敲别的命令）→ `fg` 拉回前台 → Ctrl-C 发 SIGINT 结束。

## B4

3. 机制：**每个新 shell 启动时自动 source `~/.bashrc`**（交互式 bash 的启动逻辑），别名因此被重新定义进新 shell 的内存。这就是"配置文件"的全部秘密——不是什么魔法注册表，只是开机自动执行的脚本。

## C1 参考

```bash
pidwait () {
    while kill -0 "$1" 2>/dev/null; do
        sleep 1
    done
}
```

要点：`kill -0 PID` **不发送任何信号**，只做存在性检查——进程在则退出码 0，不在则非 0（正好当条件用）；`2>/dev/null` 吞掉"无此进程"的报错；`sleep 1` 避免循环空转烧 CPU。

## C2

管道逐段：`history` 吐出历史 → `awk '{print $2}'` 取每行第 2 列（命令名；第 1 列是编号）→ `sort` 归拢相同命令 → `uniq -c` 计数 → `sort -nr` 按数字倒序 → `head -10` 取前十。之后按自己榜首命令建别名，如 `alias s='ssh myserver'`。

## C3

1. 多出 `id_ed25519`（**私钥，打死不能给**）与 `id_ed25519.pub`（**公钥**，随便分发，要装到目标服务器的 `authorized_keys`）。认证原理：服务器用公钥出题、客户端用私钥作答——私钥永不离开你的机器。
2. 模板与含义：`Host fdu`（你起的短名）`HostName 10.0.0.5`（真实地址）`User mathlover`（登录用户）`Port 22`（端口）。之后 `ssh fdu` 等价于 `ssh -p 22 mathlover@10.0.0.5`。
3. `-L 9999:localhost:8888` 把**服务器上**监听 8888 的服务映射到**本机** 9999；本机浏览器访问 `localhost:9999`。"localhost"是站在服务器视角说的（目标 = 服务器自己视角的 8888）。
