## 0. 一句话定位

学会"和计算机用文字对话"：Shell 是什么、命令怎么被解析执行、文件系统怎么导航、程序之间怎么用管道连接。**超算比赛 100% 的工作发生在这个界面里。**

## 1. 内核、Shell、终端：三个被混用的词

**直觉**：操作系统是一家餐厅——内核是后厨（真正管硬件），你是顾客，Shell 是服务员（你用文字点菜，它转达后厨，端回结果）。终端（Terminal）只是那个"点菜窗口"软件（你看到的黑框框窗口）。

**定义**：
- **内核（kernel）**：操作系统核心，管理 CPU、内存、磁盘等硬件资源，普通程序不许直接碰
- **Shell（壳）**：一个"读命令 → 找程序 → 运行 → 显示结果"的循环（REPL）。因包在内核外而得名
- **终端（terminal）**：显示 shell 的窗口程序，只负责显示与键盘输入

**提示符（prompt）解剖**：`missing:~$` 三段——`missing` 主机名、`~` 当前在家目录、`$` 普通用户（root 显示 `#`）。**提示符显示的路径会随你的移动而变**（如 `~` → `/tmp`），它和 `pwd` 是互相印证的两个证人。

## 2. 命令、参数与 $PATH

**核心规则：bash 按空格切词，第一个词是程序名，其余全是参数。**

```bash
date              # 程序 date，无参数
echo hello        # 程序 echo，参数 hello
cd 'My Photos'    # 含空格的参数用引号或 \ 转义
ls -l             # - 开头的参数叫 flag，改变程序行为
```

**bash 怎么找到程序？** 依次检查：**别名 → 函数 → 内置命令 → $PATH 目录列表**。全落空才报 `command not found`。

```bash
echo $PATH      # /usr/local/bin:/usr/bin:...
which echo      # 查某命令实际位置 → /bin/echo
/bin/echo hi    # 绕过 PATH 直接用完整路径执行
```

**为什么 `./semester` 不写成 `semester`？** 带 `/` 的词当作路径直接执行；不带 `/` 的只搜 $PATH——**当前目录永远不在搜索范围**。这是安全设计：否则有人在 /tmp 放个恶意 `ls`，你 cd 过去敲 `ls` 就中招。（Windows cmd 恰好是"先搜当前目录"，是它的著名安全隐患。）

## 3. 路径（Path）与导航

文件系统是棵倒挂的树，`/` 是根。三个特殊符号：`.` 当前、`..` 上一级、`~` **家目录**（= `/home/用户名`）。

```bash
pwd                    # 我在哪
cd /home               # 绝对路径：从 / 出发
cd ..                  # 退一级
../../bin/echo hello   # 相对路径也能执行程序
ls /home               # 列指定目录（裸 ls 只列当前目录）
```

🕷 **高频错**：`~` 是家目录不是根目录。`cd ~/..` 的结果是 `/home`（家目录的上一级），不是 `/`。

## 4. 获取帮助与权限串

三条求助路：`cmd --help`（最快）、`man cmd`（完整手册，q 退出，/ 搜索）、`tldr cmd`（例句版，建议安装）。

**必考：读懂 `ls -l` 的权限串**（10 个字符）：

```
drwxr-xr-x  1 missing  users  4096 Jun 15  2019  missing
│└┬┘└┬┘└┬┘
│ │  │  └── 其他人：r-x
│ │  └──── 同组用户：r-x
│ └─────── 所有者：rwx
└──────── d=目录（-=普通文件）
```

r=读、w=写、x=执行。**目录上的 x 含义特殊**：不是"执行"而是"进入/穿越"。

🕷 **高频错**：把目录权限想成"没读写就进不去"。正确模型——**x 是门禁卡（cd 进去），r 是索引牌（ls 列出），w 是改建权（建/删文件）**。要让人"能进入且能列出"必须 r+x 都给。

## 5. 文件操作四件套

| 命令 | 记忆点 | 作用 |
|------|--------|------|
| `cp a b` | copy | 复制（a 不变，多出 b） |
| `mv a b` | move | 移动/重命名（a 变 b，不留原件） |
| `mkdir 名` | make directory | 建目录 |
| `rm 文件` | remove | 删除——**没有回收站**，`rm -r 目录` 删整棵 |

实战习惯：`rm -r` 之前先 `ls` 一眼目标路径。比赛期间最贵的事故就是删错目录。

## 6. 流、重定向与管道——本讲灵魂

**直觉**：每个程序天生三根水管——标准输入（stdin）、标准输出（stdout）、标准错误（stderr）。默认接终端（键盘进、屏幕出），但可以拆下来接到文件或别的程序。这是 Unix 哲学的核心：**每个程序只做一件小事，用管道串起来干大事**。

```bash
echo hello > f.txt     # stdout 写入文件（覆盖）
echo world >> f.txt    # 追加，不清空
cat < f.txt            # 文件接到 stdin
ls -l / | tail -n 1    # 管道：左边的 stdout 接右边的 stdin
```

🕷🕷 **经典陷阱（本讲最重要的一题）**：

```bash
sudo echo 3 > brightness     # ❌ Permission denied
echo 3 | sudo tee brightness # ✅ 成功
```

原因：**`>` 由 shell（以你的普通身份）执行**，不是 echo——shell 去打开文件的瞬间就权限不足，此时 sudo/echo 根本还没运行。`sudo` 只能提升它后面跟着的程序。`tee` 方案里打开文件的是以 root 运行的 tee，合法。

推广规则：**文件 `/root/secret` 仅 root 可读时，`sudo cat < /root/secret` 失败、`sudo cat /root/secret` 成功**——权限检查针对"正在打开文件的进程"。

## 7. 全讲最重要的心智模型：命令行的两层

| 层 | 谁在干活 | 处理什么 |
|----|----------|----------|
| **bash 层** | 你的 shell | `>` `<` `|` `&&` `\|\|` `;` `*` `?` `{}` `$变量` `~` —— 出门前全部处理完 |
| **程序层** | 被调用的程序 | 收到的是干净的参数列表（argv） |

10 秒实验：`echo a*`（bash 先展开成文件名列表）vs `echo 'a*'`（引号挡住 bash，echo 收到字面量）。**每遇一个特殊符号问一句：这是 bash 的，还是程序的？** 一半以上的"玄学报错"死在这里。

## 8. 常见误区清单

1. 终端 ≠ shell：终端是窗口，shell 是里面干活的解释器
2. `~` ≠ `/`：家目录 ≠ 根目录
3. 目录的 x = 进入，不是"执行"
4. `>` 覆盖、`>>` 追加
5. `sudo cmd > file` 里的 `>` 不吃 sudo——重定向永远由当前用户的 shell 完成
6. `rm` 没有回收站
7. 敲 `semester` 找不到不是 bug：PATH 不搜当前目录，写 `./semester`
