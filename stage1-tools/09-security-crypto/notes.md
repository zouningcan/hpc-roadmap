## 0. 一句话定位

四个原语（哈希、KDF、对称、非对称）+ 一堆组合它们的好习惯（密码管理器、2FA、全盘加密、SSH 密钥）。你在模块 05 已经用过非对称加密（ssh-keygen），本模块讲它**为什么安全**。

## 1. 熵（entropy）：密码强度的度量

**熵 = log₂(可能性数量)**，单位 bit。

- 抛硬币：2 种可能 → 1 bit
- 掷骰子：6 种 → log₂6 ≈ 2.58 bit
- 从 10 万词的词典随机挑 4 个词：log₂(100000⁴) ≈ 66 bit

**威胁模型决定需要的熵**：~40 bit 足以抵抗**在线**爆破（有速率限制/锁定）；要抵抗**离线**暴力（攻击者拿到哈希自己慢慢算）需要 80+ bit。

推论：**密码强度来自随机性而不是来自"看起来乱"**——`Tr0ub4dour&3` 看着复杂，熵很低（字典词变形）；`correct-horse-battery-staple` 四个随机词，熵高得多。密码管理器（KeePassXC/pass/1Password）就是让你"只记一个高熵主密码，其余全部随机生成"。

## 2. 哈希函数（hash function）

`hash(任意输入) → 固定长度输出`。四条性质：**确定性**（同输入同输出）、**不可逆**、**难以定向碰撞**、**难以碰撞**。

```bash
printf 'hello' | sha1sum     # aaf4c61ddcc5e8a2dabede0f3b482cd9aea9434d
sha256sum 大文件.iso          # 现代推荐（SHA-1 已被认为不够强）
```

**应用**：
- **完整性校验**：从镜像下载 ISO，比对官方 SHA256SUMS——镜像不可信但哈希对照表可信（模块 04 的数据管道 + 本模块的信任模型）
- **Git 的内容寻址**（模块 06 讲过：对象按内容哈希命名——防篡改就是哈希函数的性质）
- **承诺方案**：先公布 `sha256(r)` 承诺、后揭示 r

🕷 **哈希存密码的正确姿势是"慢哈希 + 盐"**（见下节 KDF）——直接 `sha256(password)` 存储，攻击者拿库后用 GPU 每秒算几十亿次，形同裸奔。

## 3. 密钥推导函数（KDF）

特性：**故意设计得很慢**（毫秒级而非纳秒级）。慢对你无所谓（登录一次），对爆破者是灾难（每次猜测都要付同样代价）。

**存密码的标准姿势**：`存 KDF(密码 + 盐)`，每个用户随机盐——同密码不同盐得不同结果（防彩虹表），慢到爆破不划算。

## 4. 对称加密（symmetric encryption）

一把钥匙，加密解密同一把：`decrypt(encrypt(m, k), k) = m`。现代标准 **AES**（AES-128/256 指密钥长度）。

```bash
openssl aes-256-cbc -salt -in secret.txt -out secret.enc    # 加密（会要口令）
openssl aes-256-cbc -d -in secret.enc -out secret.dec       # 解密
cmp secret.txt secret.dec                                    # 验证一致
```

**应用**：云盘加密——文件用 `key = KDF(口令)` 加密后再上传（云厂商看不到明文）。注意 CBC 模式不认证（内容可被篡改而不被发现）；现代实践用 **AES-GCM** 等认证加密（同时保证机密性与完整性）。

## 5. 非对称加密（asymmetric encryption）

**两把钥匙**：公钥随便发，私钥打死不给（模块 05 的 SSH 密钥对就是它）。

- **加密**：公钥加密 → 只有私钥能解（机密性）
- **签名**：私钥签名 → 任何人用公钥验证（真实性 + 不可否认）

比喻：对称加密是门锁（一把钥匙）；非对称是**挂锁**——你把打开状态的挂锁发给大家，谁都能锁上寄给你，但只有你手里有钥匙开。

**应用**：
- **SSH 认证**（挑战-应答）：服务器用你的公钥出题，客户端用私钥作答——**私钥从不离开你的机器**（模块 05 讲过流程，现在你知道原理了）
- **PGP 加密邮件**、Signal 端到端聊天
- **GPG 签名的 Git 提交/标签**：`git commit -S`、`git tag -s`、`git tag -v` 验证——发布软件时证明"这确实是我发的"

**公钥怎么分发/信任**：信任首次使用（SSH 的 known_hosts 首次指纹确认——HelloHPC 签到题考的就是这个指纹）、信任网络（PGP 互相签）、社交证明（Keybase 绑定社交账号）。

## 6. 案例速览

- **密码管理器**：唯一主密码经 KDF 保护保险库，站点密码全部唯一随机
- **双因素（2FA）**：口令 + YubiKey/验证器——钓鱼偷走口令也不够用
- **全盘加密**：cryptsetup/LUKS、BitLocker、FileVault——丢笔记本不丢数据
- 🕷 **现实案例（本项目亲身经历）**：gh token 权限过宽（含 delete_repo）+ 曾把凭据经镜像中转的风险——**凭据管理是密码学落地的第一现场**，scope 最小化、用后吊销、绝不过第三方

## 7. 常见误区清单

1. "看着乱"的密码 ≠ 强密码——熵看可能性数量，不看符号花哨程度
2. 直接存密码哈希 = 裸奔：要 KDF（慢）+ 盐（随机）
3. SHA-1 已弱化（Git 也在迁移 SHA-256），新系统用 SHA-256 及以上
4. 加密 ≠ 认证：不认证的密文可被篡改，用 AES-GCM 类认证加密
5. 拿到密文和"算法保密"没关系——柯克霍夫原则：安全性只依赖密钥
6. 别自己造协议：用 OpenSSL/libsodium/age 等现成轮子
